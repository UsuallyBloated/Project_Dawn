# Session 2026-06-09 (cont.) — ALLY-target buff routing

Made beneficial buffs castable on a targeted group-mate over the wire. The handoff framed
this as "ALLY buffs wrongly apply to the caster," but the real state was different: **every
stat/haste/clarity/SoW/shield buff was authored `target_type: "SELF"`** on both client and
server, so they correctly self-applied — they were simply never ally-targetable. So this is
a feature (make buffs ally-castable), not a routing bugfix. The class design docs (cleric /
enchanter / druid / shaman / ranger / beast_master `.md`) explicitly tag each buff's base
rank `Self` / `Target` / `Group`; that drove the curated set.

## Curated ALLY set (10, designer-confirmed)

Flipped `SELF → ALLY` in both `data/spell_definitions.gd` and server `spells.toml`:
**Bless, Valor, Brilliance, Clarity, Strength, Gift of Insight, Spirit of the Bear,
Spirit of Wolf, Haste, Thorns.** Left `SELF` (documented self-only): Rune, Spellshield,
Breeze, Primal Bond, Hunter's Eye, the Bard songs (Twist mechanic), Lich Form. Note:
the Druid doc has base **Thorns as Self** (group version = the unimplemented capstone
"Ancient Thornwall"); the designer chose to keep Thorns ally-castable anyway. Spellshield
stays self.

## Changes

- **Server** (`world/tick.rs`): new `apply_player_spell_buffs(conn, spell, now)` applies the
  full beneficial set (HoT, MP-regen, speed, haste, damage shield, absorb, accuracy/crit,
  primary stat) to one recipient. The SELF arm (Lich toggle kept inline) and the ALLY
  player arm now both call it, so they stay in lockstep. ALLY arm fans the `BuffSnapshot`
  to the buffed peer + bystanders and logs `"ALLY buff applied"` (caster + target + spell)
  as the playtest log anchor. ALLY-pet arm still heal-only (no replicated pet buffs).
- **Client `autoloads/spells.gd`**: `_cast_target_id()` makes the broadcast target
  target-type-aware (ALLY → peer, or pet only when the spell heals, else self/0); buffs
  cast on a peer skip the local `BuffManager.add_*` via `_ally_target_is_remote()`; the
  ALLY PvP pre-check now covers buffs (not just heals); added `Spells.get_spell_by_name()`.
- **Client `autoloads/buff_manager.gd`**: `reconcile_with_server_snapshot()` is now
  **additive** — a snapshot buff with no local tracking is reconstructed from the spell
  definition (raw, server-authoritative values; snapshot `remaining` as duration), so the
  buffed ally's own `PlayerStats` + buff bar reflect it. Expiry/dispel still flow through
  the existing subtractive pass. Single-slot buffs only fill when empty (no clobber).

## Acceptance

Cleric casts Bless on a group-mate → server applies the StatBuff to the target conn +
fans `BuffSnapshot` → the group-mate's client reconstructs it (WIS goes up, bar shows
Bless) → on server expiry the snapshot drops it and the stat returns. Caster is no longer
buffed when targeting a peer.

## Playtest round 1 (2026-06-09) — two real bugs + one false alarm

First two-client run surfaced three findings; `server.log` triaged them:

- **SoW / Thorns "don't land on target" → false alarm.** Every SoW/Thorns cast logged
  `spell cast rejected — insufficient mana` (caster stuck at mp=15.0). Regen is currently
  disabled (commit 835d442), so the caster drained and couldn't cast. When mana was up,
  `ALLY buff applied … target=47` fired for Bless/Strength/Clarity/Haste — routing is fine.
  Top up mana (Test Panel Full Heal fills MP, or food/drink) to actually test SoW/Thorns.
- **"Stat buffs won't stack" → real, fixed.** Server stacks stat buffs (keyed by name —
  Bless's +WIS and Strength's +STR both land on the target conn), but the client's
  `_primary_stat_buff` was a **single slot**. Converted to a multi-slot list
  (`_primary_stat_buffs`): `add_primary_stat_buff` appends + refreshes by name,
  `_undo_one_primary_stat_buff(name)` undoes a single entry, and `_process` / reconcile /
  `clear_all` / snapshot all iterate. `hud_buff_bar.gd` now renders one icon per stat buff
  keyed `primary_stat:<name>` (mirrors the existing HoT pattern). Other buckets stay
  single-slot (mp_regen / shield / absorb are exclusive on the server too — consistent).
- **`/pvp on` blocks buffing a group-mate → real, fixed.** `combat::can_attack` is just
  `a.pvp_override_on && b.pvp_override_on` — no group check — so two grouped /pvp-on players
  read as mutually attackable and the ALLY gate rejected the beneficial cast. Added
  `GroupManager::same_group(a, b)`; the ALLY heal/buff gate (player + pet arms) now rejects
  only when `hostile && !allied`. (This was partly masked by the mana drought in the log.)

Server rebuilds clean; client refactor verified by re-read. Re-export + restart the server,
top up mana, and re-run the checklist.

## Playtest round 2 (2026-06-09) — the mana drought was a tooling bug

Round 2's "buff doesn't land on target" results (Valor/Brilliance/Bear/Insight, SoW/Thorns,
bystander) were all the **same false alarm**: `server.log` shows every one rejected with
`spell cast rejected — insufficient mana` (caster pinned at mp=15). The stacking + group
fixes are still **unverified** — no peer buff actually fired.

Root cause of the unescapable drought: **Test Panel → Full Heal restored MP client-side
only** (`test_panel.gd::_full_heal` set `PlayerStats.mp` locally with a comment claiming MP
"isn't server-driven"). But the server gates mana independently, so the bar looked full
while the server still rejected every cast. Three fixes:

- **`handlers.rs` `HealSelf`** now also restores MP + stamina to full (it backs the dev Full
  Heal button; server-authoritative, so this is the only path that unblocks casting).
- **`test_panel.gd::_full_heal`** always sends `broadcast_heal_self` in launcher mode (even
  at full HP) so a drained-mana top-off reaches the server.
- **`tick.rs`** now fans a `CastFail("Not enough mana.")` on the insufficient-mana rejection
  (was a silent `continue`). The caster sees "Cast failed: Not enough mana." in the combat
  log instead of just the optimistic "You cast X". (Player-reported: the client showed "You
  cast X" with no error because Full Heal had lied the local MP to full, passing the local
  mana check while the server silently rejected.)

Server rebuilds clean. Re-export + restart, click Full Heal (now actually restores castable
mana), and the buff stacking / group-buff / SoW / Thorns rows are finally testable.
