## Save persistence — Tier 2 (inventory + equipment)

### M1 — Base / public stat split (`autoloads/player_stats.gd`)
The fundamental fix that makes inventory persistence safe.

- New shadow fields: `_base_strength`, `_base_dexterity`, `_base_agility`, `_base_intelligence`, `_base_wisdom`, `_base_charisma`, `_base_constitution`, `_base_max_hp`, `_base_max_mp`, `_base_max_stamina`
- Public stat fields keep the live (gear + buff inclusive) value used for combat math and UI everywhere
- `apply_character` writes both intrinsic and public to the same gear-free baseline
- `_level_up` advances both, including the CON-derived max_hp adjustment
- `apply_item_bonuses` / `remove_item_bonuses` already only touched public fields (no change needed); `BuffManager` primary stat buffs and `Transformations` max_hp tweaks verified to do the same
- `save_state` writes `_base_*`; `load_state` restores `_base_*` and mirrors them to public (no gear is equipped at load time, so they match)

### M3 — Atomic file writes (`autoloads/save_manager.gd`)
- `save()` writes to `character.save.tmp`, rotates the previous primary to `character.save.bak`, then renames tmp to primary. A crash mid-write leaves either the previous good save or a recoverable .bak.

### M2 — ItemData dual save format (`scripts/item_data.gd`)
- New methods: `to_save_dict()`, `_to_snapshot()`, `static func from_save_dict(d) -> ItemData`
- `.tres`-backed items save as `{"path": "res://..."}`; runtime-built items (no resource_path) save the full ~30-field snapshot
- Loader prefers `path`, falls back to `snapshot`. Texture2D icon serialised by resource_path.

### Inventory + Equipment save/load
- `autoloads/inventory.gd` — `save_state()` serialises `base_slots[8]` plus `bag_contents[8][]` as parallel arrays. `load_state` clears slots, rebuilds bags only when the bag itself reloaded successfully and the size matches. `_slot_to_dict` / `_slot_from_dict` helpers.
- `autoloads/equipment.gd` — `save_state()` writes the 9 paperdoll slots. `load_state` defensively un-equips any current items first (removing their bonuses), then re-equips from save; each `_apply_stat_bonuses` adds fresh bonuses onto the gear-free PlayerStats baseline.

### SaveManager strict load order (M4)
1. **Alignment** first — `get_effective_class` must be correct when PlayerStats fires `character_applied`
2. **PlayerStats** — gear-free baseline; triggers CharacterSetup, which initialises skill trackers to class defaults
3. **Skill trackers** — overwrite the class defaults with saved values
4. **Quests**
5. **Inventory** — items into slots; no stat changes
6. **Equipment** **last** — re-equips items; `apply_item_bonuses` adds bonuses cleanly on top of step 2

- `scripts/lobby.gd` — `_on_delete_save_pressed` clears `character.save`, `character.save.tmp`, and `character.save.bak`; status label confirms

## `.tres` ItemData class-cache fix

### Problem
`load("res://data/loot/items/copper_ore.tres") as ItemData` returned null in the test panel even though production paths (loot drops, vendor stock, mining, crafting recipes) all use the same pattern successfully. Root cause: `[gd_resource type="ItemData"]` headers depend on Godot's GlobalScriptClassCache resolving "ItemData", which is fragile when scripts get edited mid-session.

### Fix — bulk converted 155 ItemData `.tres` files
From:
```
[gd_resource type="ItemData" load_steps=1 format=3]
[resource]
item_name = "..."
```
To:
```
[gd_resource type="Resource" script_class="ItemData" load_steps=2 format=3]
[ext_resource type="Script" path="res://scripts/item_data.gd" id="1_item"]
[resource]
script = ExtResource("1_item")
item_name = "..."
```

The explicit script reference removes dependence on the class-name registry. Verified zero files remain in old format; LootTable `.tres` was scanned but `newbie_zone.tres` is an unused orphan (loot is built at runtime via `MobLootTables.build`).

### Test panel restored
- `scripts/test_panel.gd` `_give_crafting_materials` — full 34-item seed list restored. Dict literals use explicit string keys (`{"p": "..."}`) instead of identifier syntax to dodge any Variant-coercion fragility. Error reporting distinguishes load failures from inventory-full skips.
