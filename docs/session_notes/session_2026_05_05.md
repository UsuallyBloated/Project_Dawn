- `autoloads/equipment.gd` — `save_state()` writes the 9 paperdoll slots. `load_state` defensively un-equips any current items first (removing their bonuses), then re-equips from save; each `_apply_stat_bonuses` adds fresh bonuses onto the gear-free PlayerStats baseline.

## `.tres` ItemData class-cache fix

### Problem
`load("res://data/loot/items/copper_ore.tres") as ItemData` returned null in the test panel even though production paths (loot drops, vendor stock, mining, crafting recipes) all use the same pattern successfully. Root cause: `[gd_resource type="ItemData"]` headers depend on Godot's GlobalScriptClassCache resolving "ItemData", which is fragile when scripts get edited mid-session.

### Fix — bulk converted 155 ItemData `.tres` files
From:
```
[gd_resource type="ItemData" load_steps=1 format=3]
[resource]
item_name = "..."
```
To:
```
[gd_resource type="Resource" script_class="ItemData" load_steps=2 format=3]
[ext_resource type="Script" path="res://scripts/item_data.gd" id="1_item"]
[resource]
script = ExtResource("1_item")
item_name = "..."
```

The explicit script reference removes dependence on the class-name registry. Verified zero files remain in old format; LootTable `.tres` was scanned but `newbie_zone.tres` is an unused orphan (loot is built at runtime via `MobLootTables.build`).

### Test panel restored
- `scripts/test_panel.gd` `_give_crafting_materials` — full 34-item seed list restored. Dict literals use explicit string keys (`{"p": "..."}`) instead of identifier syntax to dodge any Variant-coercion fragility. Error reporting distinguishes load failures from inventory-full skips.

## `crates/projectdawn-server`

### Auth WS service (`src/auth/mod.rs`)
- `serve(cfg, pool)` — production accept loop; `serve_bound(cfg, pool) -> (SocketAddr, JoinHandle)` — variant that returns the bound addr so integration tests can use port 0.
- One Tokio task per connection. `tokio-tungstenite::accept_async` for the WS upgrade, `serde_json` for frames. Ping/pong handled inline; binary frames rejected with InvalidInput; malformed JSON returns InvalidInput rather than dropping the connection.
- Stateless past the session token. Every authenticated message carries its own `session_token` (hex of 32 random bytes).

### DB layer (`src/db/mod.rs`)
- `open(url)` builds an `SqlitePool` with 8 max connections; `migrate(pool)` runs the bundled migrations.
- `create_account` — Argon2id hash via `argon2 0.5.3` (default params), `OsRng` salt.
- `verify_login` — CASE-INSENSITIVE username lookup, banned check, password verify, then `issue_session`.
- `issue_session` — 32 OsRng bytes, hex-encode for transport, store as BLOB; expires_at = now + 30 min.
- `touch_session` — refreshes `last_seen`, returns the account_id; expired or unknown tokens → `SessionExpired`.
- `revoke_session` — DELETE on logout.
- `list_characters` / `create_character` / `delete_character` — soft delete via `deleted_at`.
- Validation (`validate_username` / `validate_password`, char-name rules) lives in this module so it's enforced once.
- Uses runtime `sqlx::query` / `query_as`, not the compile-time `query!` macros, so the build doesn't need a live DATABASE_URL.

### Error model (`src/error.rs`)
- `AuthError` thiserror enum maps 1:1 to `protocol::auth::ErrorCode`. `Internal(anyhow::Error)` hides server-side detail from the user-facing message. `From<sqlx::Error>` and `From<argon2::password_hash::Error>` wrap into Internal.

### Config (`src/config.rs`, `src/main.rs`)
- Reads `PROJECTDAWN_AUTH_BIND` (default `0.0.0.0:8765`), `PROJECTDAWN_WORLD_ENDPOINT` (default `127.0.0.1:7777`), `PROJECTDAWN_DATABASE_URL` (default `sqlite://world.db?mode=rwc`), `PROJECTDAWN_MIN_CLIENT_VERSION` (default `0.1.0`).
- Inline 25-line semver parse + comparison; full `semver` crate not pulled in for one feature.
- `main.rs` has a 25-line `.env` loader so `dotenvy` isn't a dep.
