## 2. Six characters, made over the auth socket

`ported_spells_checklist.md` needs six classes at six levels. The hosted server's auth port is
reachable from the dev box (the launcher's own path), so a small tool now does what the
launcher would: `crates/projectdawn-server/examples/provision_test_characters.rs` (server
`f8f1ef3`). It registers an account with a random password printed once, creates the
characters (falling through to the next candidate name when one is taken, since names are
unique world-wide), and prints the sqlite command the operator runs on the host to set the
levels. That command is the integration tests' own `set_char_level`: the loader recomputes the
maxima from the level and clamps the stored values down, so a character bumped this way logs
in at full health at its new level.

Run against the R720 tonight: account `spelltest` (id 3), characters Embris (Sorcerer 10),
Rimewind (Wizard 10), Mirelle (Enchanter 20, for the charm spot check), Caderyn (Bard 10),
Fennric (Beast Master 4), Aldous (Paladin 12), ids 5 to 10. The password went into
`docs/deployment/test_accounts.md` (untracked) and to the user in chat; the levels wait on the
user running the printed command. Nothing privileged: public register, login and create
messages, an ordinary non-GM account.

## 3. The ported-spells sitting: both suspicions confirmed in play, both fixed

The user ran `ported_spells_checklist.md` §4 on the `spelltest` characters and pasted the
journal. Both suspected bugs from the 10-05 review are real:

- **Charm** (Mirelle): the pet appeared as a blue capsule and vanished. The log shows
  `charm expired` 50 ms after each charm, twice. The decay sweep compared
  `now.duration_since(exp) >= 0.0`, and `duration_since` saturates to zero while `exp` is
  still ahead, so the test was true on the next tick. Now `now >= exp`.
- **Leash** (Caderyn, Chorus of Misery): Plagued Zombies came at once, the Wild Boar stood
  and took it until the bard walked closer. `tick_idle` acquires an attacker only inside
  `leash_range()`, which defaulted to aggro x 2 (the boar: 20 m) while spells reach 25 m.
  New `MIN_LEASH_RANGE = 30.0` floors the leash of every mob with an aggro radius; aggro-0
  dev dummies stay passive; a long leash is untouched.

Server `6a802f4` on the deploy branch (trade branch merged, `8e83b97`), 251 unit and 68
integration tests green. Each fix carries a test that fails on the previous code: the charm
test now asserts no despawn for 1.5 s after the PetSpawn; a new integration test nukes a
1 m-aggro dummy from 20 m and waits for the `EntityTarget`. The leash test's first cut
passed on the old code: the dummy (aggro 8) had noticed the caster at spawn, 3 m away, and
that stale target message sat in the queue. It now reads the distance off the server's own
Position fan and asserts the mob targeted nobody before the nuke. Built ahead of the batch
plan's approval: both are proven bugs on the host, not design; the other four parts of step
0 still wait on the plan.
