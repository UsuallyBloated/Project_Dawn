# Session 2026-06-22 — Corpse Epic, Slice 0: Server-Authoritative XP / Leveling + Death Penalty

Cross-wire, both repos, **PD_W0017 to PD_W0018**. The foundation slice of the corpse / resurrection
epic (`docs/design/corpse_and_resurrection_plan.md`): move XP, level-ups, AND the death penalty
server-side so Slices 1 to 3 (the corpse run, retrieval, Cleric res) can apply an authoritative XP
loss + de-level that the client can't roll back. Invisible to the player except that leveling now
sticks. Branch `feature/ally-buff-routing`. **Not committed — awaiting the user's playtest.**

## The problem this fixes

Leveling was a split-authority mess (the `[[project-level-up-server-desync]]` bug, verified by reading
the code this session, a recon agent had wrongly claimed the server awarded no XP at all):

- The server **already** awarded kill XP (`tick.rs` solo spell-kill + group-split melee + pet-kill
  branches via `send_xp_gained`), but `send_xp_gained` was a pure notification, `current`/`to_next`
  were hardcoded `0` and it never touched `conn.xp`/`conn.level`. The server's level stayed frozen.
- The **client** owned leveling: `_on_xp_gained` to `PlayerStats.gain_xp` to a local `_level_up`.
- So the client leveled (max HP climbed), then the server's next `HealthUpdate` (max stats computed
  from the *stale* server level via `char_data::compute`) rolled it back.

The stat tables were verified in full lockstep first (all 18 classes + `_default` + the per-level
apply structure + the 1.5x xp curve match between client `CLASS_LEVEL_GAINS` and server
`char_data::level_gains`, anchor-tested), so moving authority to the server shifts no one's stats.

## Decisions (locked with the user 2026-06-22)

- **Death penalty = 5% of the current level's XP band** (`xp_to_next`), cascading past the boundary
  with **no per-death cap**. **No penalty below level 5**, and a cascade **never drops below level 5**
  (grace line == floor line). No skill/AA loss.
- **Coins strip to the corpse** on death (Slice 1), banked coin safe. (Recorded for Slice 1.)
- Slice 0 does the **full leveling port**, not a minimal death-delta. Quest XP also moves server-side.

## Server (`F:/Projects/server`)

- **New `world/progression.rs`** — the single XP/leveling authority. `award_xp(server, conn, amount)`
  mutates `conn.xp`, resolves level up/down via a pure, unit-tested `resolve(xp, level)`, applies the
  per-level **intrinsic delta** to `conn`'s running totals (add-only, so gear + buff bonuses already
  baked in survive, never overwrite with `compute()`'s gear-free value), and sends `XpGained`
  (+ `LevelUp` on a level change). `apply_death_penalty` (5% band, cascade, grace/floor 5) and
  `kill_player` (penalty + on-death resets) live here. **7 unit tests** (spill, multi-level, cascade
  de-level, floor at 5, penalty fraction).
- `char_data.rs` — new `xp_to_next_for(level)` helper (extracted 1.5x loop).
- `handlers.rs` — `send_xp_gained` now carries real `current`/`to_next`; new `send_level_up`. The
  `GrantQuestXp` handler routes client-tracked quest XP through `award_xp`. `DeathBroadcast` rewritten
  to call `kill_player` (guarded by `death_processed`); `Respawn` clears the flag.
- `tick.rs` — the three kill-credit sites now call `award_xp` instead of `send_xp_gained`; a new
  **post-combat death sweep** (step 5a-bis) detects any in-world player at `hp <= 0` and not yet
  processed, runs `kill_player`, fans `EntityDied`, sets `death_processed`. This is the
  server-authoritative death detection (the client's `DeathBroadcast` now only covers death causes the
  server doesn't simulate, e.g. client fall damage).
- `connection.rs` — `death_processed: bool` on `PerConnection`.
- **No resource fan on level-up:** the client applies the intrinsic max-pool delta itself (lockstep),
  and the regular `HealthUpdate` stays the idempotent-assign backstop — avoids a level-up/HealthUpdate
  double-count and keeps one client code path.

## Wire (PD_W0017 → PD_W0018)

- `LevelUp { new_level }` (was inert) reshaped to `{ new_level, xp, xp_to_next }` (up on gain, DOWN on
  a death penalty). `XpGained.current/to_next` now meaningful. New `ClientWorldMsg::GrantQuestXp
  { amount }` appended. gdext-net: `LevelUp` decode + `level_up` signal + `send_grant_quest_xp`. **DLL
  rebuilt** (4.08 MB, release +crt-static).

## Client (this repo)

- `player_stats.gd` — `_level_up` refactored to a shared `_apply_level_gain` (+ new `_apply_level_loss`
  reverse). New `apply_server_level(new_level, xp, to_next)` applies the intrinsic delta up or down to
  both public and `_base_` stats (so equipment deltas survive), no local heal (server owns hp). New
  `apply_remote_xp(amount, current, to_next)` mirrors the bar; no local level-up.
- `net.gd` — `_on_xp_gained` to `apply_remote_xp` (+ a "You lost N experience" line on a negative
  amount); new `_on_level_up` to `apply_server_level` (the inherited gdext `level_up` signal); new
  `grant_quest_xp` sender.
- `quest_manager.gd` — in launcher mode sends `GrantQuestXp`; Test Room still grants locally.
- `player_death.gd` — removed the client-side 5% XP loss (server owns it now); `XP_LOSS_PERCENT` gone.
- `test_panel.gd` — new **Grant 250 XP** button (test aid to reach level 5+ without grinding).

## Caveats / follow-ups

- **One-time migration:** existing characters reflect their *server*-stored level on first PD_W0018
  login (leveling was client-only before, so the server's level is likely low). Expected; noted in the
  checklist.
- A stale in-flight `HealthUpdate` (pre-level max) arriving right after a level-up can briefly flicker
  max HP, self-corrects on the next update. Far better than the old permanent rollback.

## Playtest 1 follow-up (2026-06-22): two issues found, partly fixed

Leveling, de-level, grace/floor at 5, persistence, and group split all verified working in the
two-client playtest (server.log shows 34 level changes + 13 kill-credit grants + clean de-levels with
the level-5 floor holding). Two rows flagged issues; investigated via a multi-agent workflow with
adversarial verification, then fixed the safe parts:

- **HP bar "bounces" on direct heals (pre-existing, not a Slice 0 regression).** In launcher mode the
  client applied self-heals/hp-costs locally AND larger than the server (`spells.gd` added
  `WIS*0.3 * effectiveness`; the server applies flat `heal_amount`), so the bar jumped to the client
  guess then snapped down to the authoritative value. **Fixed:** gated the local self-heal + hp-cost
  writes in `spells.gd._apply_spell` behind `not Net.is_launcher_mode()` (server HealthUpdate is now the
  sole HP authority, matching regen.gd and the HoT tick). Also numbered the XP combat-log line.
  **Deferred (documented, not fixed):** (1) heal magnitude reconciliation — the displayed heal is now
  the server's flat value (no WIS bonus) and there's a client/server spell drift (server "Mending Rk. II"
  38 vs client "Mending" 25); (2) **bard songs** still bounce because they pulse client-only (the server
  applies the song heal once on cast and never pulses) — fixing needs server-side song pulsing, a gate
  would break repeated song healing; (3) consumable heals (`bag_window`/`inventory_window`) are the same
  unguarded class but were masked (heal=0 items) — gate them once the launcher consumable flow is checked.
- **Quest XP "can't tell."** The Test Panel quest was uncompletable (its "Report back to Captain Aldren"
  objective has no type and there's no turn-in NPC, so `complete_quest` never fired and `grant_quest_xp`
  was never reached — the grant chain itself is correct). **Fixed for testing:** Test Panel **Complete
  Test Quest** button (force-completes `test_q1`), a `"quest xp grant"` server log line, and numbers in
  the XP combat-log line. **Deferred (real gap, documented):** kill-objective quests can't progress in
  launcher mode at all — `notify_kill` only fires from local Test-Room `enemy.gd`, never for
  server-driven RemoteEnemy kills; routing it needs a killer-private signal (not the EntityDied
  broadcast, which would credit every witness).

Fixes touched `spells.gd`, `combat_log.gd`, `test_panel.gd` (client) and `handlers.rs` (server log
line). Server build + 143 lib tests still green; clean editor boot. Still not committed — re-playtest
the heal bar (smooth fill, no snap-back) and the Complete-Test-Quest grant before committing.
