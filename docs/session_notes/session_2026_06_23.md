# Session 2026-06-23 — Corpse Epic, Slice 1: The Corpse Run (corpse entity)

Cross-wire, both repos, **PD_W0018 to PD_W0019**. The first *visible* slice of the corpse / resurrection
epic (`docs/design/corpse_and_resurrection_plan.md`): dying leaves a **persisted corpse** holding all
your gear + carried coin; you respawn **naked**; the corpse renders with a "<name>'s corpse" nameplate,
survives a relog, and **decays harshly** (gear gone for good) after a tunable linger. Looting the corpse
back is Slice 2. Built on Slice 0's server-authoritative death (`kill_player` / death sweep). Branch
`feature/ally-buff-routing`. **Not committed, awaiting playtest.**

## Approach

A corpse is "a `LootBag` that persists to the DB, is owner-only, and decays harshly." Opened with a
3-agent read-only recon mapping the LootBag/AOI/decay template, the inventory-strip + persistence + boot
paths, and the client loot-bag render, then mirrored them.

## Server (`F:/Projects/server`)

- **Migration `0007_corpses.sql`** — `corpses` (corpse_id PK = the minted EntityId, char_id, owner_name,
  zone, pos, four coin columns, created_at) + `corpse_items` (corpse_id, flat slot, item_path, count).
- **`world/corpses.rs`** — `Corpse` struct (mirrors `LootBag`, owner-keyed) + `CORPSE_LINGER_SECS`
  (300s, test-friendly; raise for prod).
- **`db/mod.rs`** — `save_corpse` (atomic INSERT corpse + items), `load_corpses` (all, at boot),
  `delete_corpse` (explicit two-table, FK-pragma-independent).
- **`inventory.rs`** — `all_stacks()` (flatten equipped + base + bags to (item_path, count)) +
  `clear_all()` (empty everything).
- **`loot.rs`** — corpses mint from the loot-bag partition (`mint_bag_id`); `reserve_bag_ids_through`
  advances the atomic past the max boot-loaded corpse id so a fresh bag can't reuse a persisted id
  (the atomic resets on restart but corpses persist).
- **`tick.rs`** — boot-load corpses + seed AOI + reserve ids BEFORE the loop (so before any login).
  Death sweep now also moves each dead player's gear + coin onto a corpse: phase 1 collects the dead;
  phase 2 (outside the `values_mut` loop, so it can await the DB) does the **atomic gear move** —
  `save_corpse` FIRST (durable before we touch the player; on failure we skip the strip so gear is never
  lost), then `clear_all` + `recompute_equipped_stats` + zero coins + `save_inventory(empty)` +
  `save_coins(0)`, fan the emptied inventory snapshot (drives the naked respawn) + gear-free resources +
  zeroed wallet, then insert the corpse into the map + AOI and fan `CorpseSpawn`. Corpse decay sweep
  (mirrors `expired_bags`) despawns + removes from map/AOI + `delete_corpse`. Corpses also seed on
  EnterWorld + AOI cell-entry (relog / walk-back) and despawn on AOI exit, sharing the loot-bag id
  partition.
- **Wire PD_W0018 to PD_W0019** — appended `ServerWorldMsg::CorpseSpawn { corpse_id, owner_id,
  owner_name, pos }` + `handlers::fan_out_corpse_spawn`. gdext: `CorpseSpawn` decode + `corpse_spawn`
  signal. DLL rebuilt (4.09 MB).

## Client (this repo)

- **`scripts/corpse.gd`** (`Corpse`, Node3D) — a flat desaturated body + faint red glow + billboarded
  "<owner>'s corpse" nameplate. Render-only; Slice 2 adds the loot interaction.
- **`autoloads/remote_corpse_manager.gd`** — mirrors `RemoteLootBagManager` (spawn/despawn/rehydrate),
  guards the shared-partition `EntityDespawn` on `_spawn_data.has(id)`, and logs "Your corpse rests
  where you fell." to the owner on first sighting. Registered as an autoload.
- **`net.gd`** — `world_corpse_spawn` signal + handler + connect (the inherited gdext signal).
- **`combat_log.gd`** — "You have died." on `PlayerDeath.player_died`.
- Naked respawn needs no new client code: the emptied inventory snapshot already clears inventory +
  paperdoll, and `CoinsUpdate(0)` zeroes the wallet.

  (boots a server + applies migration 0007). Client: headless `--editor` boot clean (`Corpse` class

## Caveats / follow-ups

- **Cross-zone bind corpse rendering:** zone travel is a client-side scene change and the server's view
  of the player position doesn't follow a teleport, so a corpse could draw in a *different* bind zone.
  No issue for a no-bind character (same-scene respawn). Tied to the deferred server-authoritative
  respawn / Soul Binder.
- Corpse `zone` / `items` / `coins` are persisted but only consumed in Slice 2 (retrieval).
- Next: **Slice 2** (loot your own corpse, reuse the loot path, owner-only), then Slice 3 (Cleric res).

## Playtest 1 follow-up (2026-06-23): two fixes (server-only)

Slice 1 playtested clean (persistence, harsh decay, atomic strip, naked respawn, two-client, AOI all
verified against server.log). Two fixes from the notes, both server-only (no wire/client change, just
restart the server to pick them up):

- **Every death path now leaves a corpse, not just server-detected combat deaths.** Corpse creation was
  keyed off the death *sweep*, so a client-first `DeathBroadcast` (Test Panel Trigger Death, fall
  damage, a dying linkdead body) set `death_processed` before the sweep and got skipped, no corpse.
  Fixed by setting a new `corpse_pending` flag in `progression::kill_player` (called by every death
  path) and keying the corpse-creation pass off that flag instead of the sweep's collection.
- **A death with nothing to leave still drops a corpse.** Removed the "naked + broke → no corpse" skip:
  an empty corpse is the Cleric's resurrection anchor (Slice 3), so a player who dies mid-corpse-run
  with nothing on them still needs a body to be rezzed to. Empty corpse = a `corpses` row with no items;
  renders + decays like any other.

143 lib tests still green. Awaiting a quick re-test (restart server; Trigger Death should now drop a
corpse, and a naked death should drop an empty one) before committing.

**Open direction (not built):** monster loot-bag orbs should become corpses too ("all creatures leave a
corpse"). Recommended for AFTER Slice 2, where corpse-looting naturally unifies players + monsters into
one lootable-corpse path + shared body visual (rather than a throwaway orb-mesh swap now). User locked
the visual: generic body now, eventually per-creature model/scale.

# Corpse Epic, Slice 2 (same day): Loot Your Own Corpse — PD_W0019 to PD_W0020

Cross-wire, both repos. A corpse becomes lootable BY THE OWNER: walk back, click your body, take your
gear (returns to bags, EQ-style manual re-equip) + coin. Opened with a 3-agent recon workflow over the
loot-intent path; the key finding (corroborated by my own read) was that the wire/handler/grant path
all reuse verbatim — only the *apply step* branches on whether the looted id resolves to a corpse vs a
loot bag.

**Decisions (with the user):**
- **Reuse `LootItem`/`LootAll` keyed by the corpse id** (no new client intent — corpses share the
  loot-bag id partition); the server resolves the `corpses` map first, then loot bags.
- **One new owner-only `CorpseContents { corpse_id, items, coins }`** (PD_W0020), sent PRIVATELY to the
  owner so peers see the body but never the gear list. Re-sent after each partial loot.
- **Looted-empty corpse despawns**, but a corpse *born* empty (naked death) lingers as a res anchor —
  the despawn fires only from a loot action, not from the empty state.

**Server:** new corpse branch in the loot apply loop (`tick.rs`): owner-only (`corpse.owner_char ==
looter`, else "That is not your corpse."), no group/RR/coin-split (coins 100% to the owner), gear via
the same `add_item_locating` + `InventoryDelta` + `LootGranted` + leftover-refund path; **atomic
persistence** via new `db::apply_corpse_loot` (looter inventory + wallet AND corpse items + coins in ONE
sqlx tx, so a crash can't dupe/lose — unlike transient bags which persist lazily); re-send
`CorpseContents` after each take; on looted-empty, `delete_corpse` + EntityDespawn. `CorpseContents`
seeded to the owner at the three CorpseSpawn sites (death, AOI-entry, relog). `handlers::send_corpse_contents`.

**Client:** `scripts/corpse.gd` becomes an `Area3D` (clickable, owner-gated `_on_input_event` -> the
shared `Loot.show_window`) with a LootWindow data surface (`items` / `coin_*` / `has_coins()` /
`bag_id` = corpse_id / `items_changed`). `LootWindow._init` + `Loot.show_window` widened off the
`LootBag` static type to duck-type a corpse. `RemoteCorpseManager` consumes `world_corpse_contents`
(materializes items, pushes onto the node, emits `items_changed` so the open window refreshes);
`net.gd` signal/handler/connect. Take/Take All already send `LootItem/LootAll(bag_id=corpse_id)`, so the
existing grant/refresh/despawn client paths work untouched. DLL rebuilt to PD_W0020.

**Verified:** server build + 143 lib tests green; clean editor boot. Live looting (take/take-all, coin
credit, owner-only, no dupe/loss, partial-loot persistence, looted-empty despawn) is the user's playtest
(`docs/playtest_notes/corpse_slice2_checklist.md`). **Not committed — awaiting playtest.** Next after
this: the monster-orb -> corpse unification, then Slice 3 (Cleric resurrection).

**Quick-playtest log review fix (server-only):** the server.log showed corpse looting working (boot
loaded 5 corpses, 5 `corpse looted empty — despawned`, no errors, no persist failures), but it surfaced
an edge: the despawn-on-empty fired even for a corpse that was ALREADY empty (a naked-death res anchor)
if the owner clicked Take All on it (the window always has a Take All button), deleting the res anchor.
Fixed by gating the despawn on `had_content` (captured before the take): a corpse only despawns if THIS
loot emptied a corpse that had something; a born-empty corpse lingers even when Take-All'd. 143 tests
still green.

**Post-playtest fix — corpse-loot atomicity (2026-06-24).** After the full playtest passed (corpse run,
persistence across a server restart, decay, loot-bag regression, coins-100%-to-owner all confirmed in the
logs / by the user), a pre-commit adversarial review (4-dimension workflow + per-finding verification)
surfaced one real MAJOR defect: the despawn + `delete_corpse` ran even when `apply_corpse_loot` FAILED.
Because `delete_corpse` was a SEPARATE tx, a failed persist + a successful delete could remove the corpse
(and its items) from the DB while the looter's inventory was never written — an item-loss window the
atomic tx was supposed to prevent. Fixed by: (1) folding the corpse delete INTO `apply_corpse_loot`'s
transaction (new `delete_corpse: bool` arg) so the body is removed atomically with the inventory write;
(2) gating the in-memory despawn on persist SUCCESS; (3) DEFERRING every client message (coins, inventory
deltas, loot-granted) until the persist commits; (4) on persist failure, REVERTING the in-memory drain
from a pre-loot snapshot (`PlayerInventory` now derives `Clone`) so the corpse + bags match the
rolled-back DB — no dupe, no loss — and sending the owner a "couldn't loot — try again". The linger rule
moved into a named predicate `corpse_emptied_by_loot()`. New regression tests (146 lib tests, +3): the
linger truth-table, plus two DB tests asserting a partial loot rewrites the corpse row while a full loot
deletes it in the same tx as the inventory write. Wire/DLL/client unchanged (server-internal fix).
