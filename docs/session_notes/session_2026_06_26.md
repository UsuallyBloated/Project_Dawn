# Session 2026-06-26 — EverQuest-authentic XP leveling overhaul

Both repos, branch `fix/xp-leveling-overflow`. **No wire change** (xp stays i32, still PD_W0022, no DLL rebuild).

## What + why

The Slice 3 resurrection playtest surfaced a real Slice-0 bug: the XP curve was geometric **×1.5/level stored
as i32**, and the `(x as f32) * 1.5` band **saturated at i32::MAX (~2.1B) around level 43** — every level from
43 to the cap shared one ~2.1B band, and a high-level death "lost" ~107M XP (the giant res-refund numbers).
See [[project-xp-curve-i32-overflow]].

The fix went through **two passes in one day**:
1. **Interim flatten ×1.5 → ×1.25 geometric** (base 100, f64 for client/server lockstep, `XP_BAND_MAX` safety
   cap, `MAX_LEVEL=60` cap in `resolve()`, `saturating_add`, and a `db::load_character` reconciliation of
   old-curve saves). Built, adversarially reviewed, **playtested clean** (`xp_curve_flatten_checklist.md`).
2. **Then superseded by the EQ-authentic model** after a research pass (`docs/design/everquest_xp_curve_reference.md`,
   compiled by another session, 3-vote-verified against P99/EQEmu/TAKP) showed cubic is both more authentic AND
   *gentler* at the high end (×1.25 grows ~70,000× over L10-60 vs EQ cubic's ~197×). The user chose to go full
   EQ. The geometric curve is gone.

## The EQ model (shipped)

**Per-level cost is CUBIC + hell levels** (`char_data.rs`): `total(L) = L³ × 1000 × hell_mod(L)`, band =
`total(L) − total(L−1)`, computed f64 + `round()`. `hell_mod` is the P99 table (1.0 for 1-29; 1.1/1.2/1.3/1.4
at the 30/35/40/45 brackets; 1.5/1.6/1.7/1.9/2.1/2.3/2.5/2.7/3.0/3.1 for 51-60). Reproduces the P99 table
**exactly**: band(1)=1,000, band(30)=5,311,000, band(60)=53,463,000, total(60)=669,600,000. Bands are
**non-monotonic by design** — band(59)=89,334,600 > band(60)=53,463,000 (the famous L59 triple-hell; entering a
hell level costs more than leaving it). `xp_to_next_for` clamps to `MAX_LEVEL` so the cubic can't overrun i32
(it would near level ~70). `compute()` now just calls `xp_to_next_for`. Mirrored byte-for-byte in
`autoloads/player_stats.gd` (`_hell_mod`/`_total_xp`/`_band_for`; the review computed both curves 1-60 and
diffed: zero differences).

**Per-kill reward is QUADRATIC** (`world/progression.rs`): `kill_xp(mob_level, zem) = (mob_level² × zem ×
3.5).round().max(1)`, `ZEM_NORMAL = 75` (so ~mob_level² × 262.5, EQEmu's macro). Cubic-cost / quadratic-reward
keeps kills-per-level ~11 on normal even-con levels and lets the hell levels spike (L30 ~22, L59 ~98). The
three `tick.rs` kill sites (spell / melee+group-split / pet) now derive XP from `kill_xp(mob.level)` instead of
the flat `entity.mob.xp`; `zones.rs` `MobTemplate.xp` is now legacy (`#[serde(default)]`, unread). One global
ZEM for now — per-zone ZEM is a later content pass.

Leveling pace was a conscious call: the user playtested and **kept the EQ-exact ZEM 75** (~11 kills/even-con,
~21 on safe blue-con mobs via the mob_level² scaling), to tune later if real play feels fast.
