  can only LOSE the item, never dup it.

## Playtest 2026-07-11 — passed; 3 pre-existing/dev-tool findings surfaced (both logs preserved)

Two-client playtest (`quest_phase2_sliceB_checklist.md`, run logs preserved as
`quest_phase2_sliceB_serverlog_run1.log` + the live `server.log`). **Slice B passed every
row:** the ring grants on turn-in (3× `wolf_threat` `reward=300` in the log), the full-inventory
rejection fires (`quest turn-in rejected — inventory full`) and the same character completes
after clearing a slot, the reward survives relog + a full server restart with no dup, and a
re-turn-in is rejected "already completed". Committed as the milestone.

A parallel triage workflow (2 log scans + 2 code investigations, all high-confidence)
confirmed the 3 tester findings are **NOT slice-B bugs** — the playtest merely surfaced them:

- **Gear stat bonuses don't display (real, pre-existing, all gear).** In multiplayer, equipping
  is server-authoritative and the server DOES apply the ring's AGI to `conn.agility`
  (`inventory.rs` recompute_equipped_stats), but there is **no wire message carrying the six
  primary stats** to the client, and `equipment.gd::apply_remote_equip` deliberately skips local
  stat recompute — so the character window keeps the base value. STR/CON only *look* applied
  because HP/MP/Stamina gear moves the resource bars (which ARE fanned). Hits every stat-bearing
  item, not just the reward. Fix is client-side (apply the bonuses in `apply_remote_equip`, with
  a matching remove on unequip + reconnect-clear so it can't double-count) — its own task.
- **Test Panel "ghost items" (dev-tool).** The give-item buttons call `Inventory.add_item()`
  client-only (no wire), so the server sees those slots empty and legitimately drops the reward
  into one, overwriting the client ghost (the tester's own hypothesis, confirmed; also explains
  the `EquipItem rejected — source slot empty` log lines). Real items (loot/vendor) go through
  the server and rejected correctly. Fix: a dev-gated server give-item message.
- **Test Panel Rotfang spawn (dev-tool).** `_spawn_named_enemy` spawns a client-local puppet
  (no `KillCredit`, legacy golden orb) instead of the server `DevSpawnMob` the wolves use — the
  log shows `rotfang_hunt` accepted but Rotfang never appears server-side again. Fix: route
  named spawns through `DevSpawnMob` (needs it to carry named stats).
