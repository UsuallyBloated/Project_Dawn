# Session 2026-09-25: Zone size limits research

User-commissioned research, no code changes: "how big can we make our zones? Does Godot
have a limit? Does our server? I want the world LARGE, wide open spaces and great
verticality." Full findings: `docs/design/zone_size_limits.md`.

## What was done

- Researched Godot 4.4's world-size limits (official large-world-coordinates doc):
  no hard limit; single-precision comfort band is ~4 to 8 km across for third-person,
  centered on origin; double precision needs a custom engine build plus a gdext rebuild.
- Recon of both repos (two Explore subagents, all load-bearing claims then verified by
  hand against the source):
  - Client: current world is a flat 400 x 400 m plate; one unchunked terrain trimesh;
    rendering completely untuned (default 100 m shadows, no LOD/visibility/occlusion);
    ZoneLoader is scene-swap only, `scenes/zones/` has never existed; remote entities
    take server Y verbatim with no ground snap.
  - Server: no world bounds anywhere, sparse 120 m AOI grid so empty area is free, f32
    fine to tens of km; cost scales with mob/player count (global per-tick enemy AI,
    the known idle 20 Hz rebroadcast, 77 all-player fan-outs), not area.
- **Headline: verticality, not width, is the blocker.** The server zeroes Y and mobs
  keep spawn Y forever, yet every range check is 3D distance, so a 2 m ledge breaks
  combat (mob chases to your XZ, 3D distance never drops below the height gap).
  Recommended path when scheduled: a server-side terrain height model (export the
  heightmap, pin Y to ground) rather than switching checks to XZ.
- Practical envelope written into the doc: build freely to ~4 x 4 km per seamless zone,
  4 to 8 km with a client polish pass, beyond that make it a second zone; keep playable
  terrain flat until the height model exists.

## Findings recorded

- **New Security To-Do: NaN Move direction** poisons `conn.pos` (clamp_length passes
  non-finite values) and then bypasses every `dist > RANGE` refusal (NaN comparisons are
  false): corpse/bag loot, res, attack, spell range. Verified at `connection.rs:43`,
  `handlers.rs:562`, `tick.rs:7898/8123/8406/3817`. Fix is a few-line finite check in
  the Move handler. Added to CLAUDE.md Security section.
- Enemy AOI cell crossings never fan EnemySpawn/EntityDespawn (`tick.rs:6934` runs only
  `aoi.update`), so mobs chasing into view stream Position for an unknown id; noted in
  the doc, worsens with bigger zones.
- Stale comment at `tick.rs:9174` claims enemies are not in the AoiGrid; they are.
