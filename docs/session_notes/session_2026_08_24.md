## Morning: the refusal playtest, and the bug it found

Batch 1/2 from the 23rd playtested clean, and the tester found a real bug I had half-fixed:
out-of-range casting reported "That target is too far away." but **still ate the mana**. Mana
comes off before the target-type match, so every rejection below that point charged full price;
reporting the failure was only half the job. New `refund_spell_cost()` gives it back on the
out-of-range and catch-all arms (`da36216`). The unknown-spell arm keeps its own path — the server
never deducted there, so it hands back its untouched value instead. Also raised the out-of-range
log `debug!` → `info!`, because the tester saw the chat line with no matching `server.log` entry.

Two tester notes closed from reasoning, not code: the greyed-out Buy button and equipped-items-
absent-from-Sell are the *client* already preventing those refusals, which is better than a server
reply; and cast cooldowns are exactly why chat can't be flooded.

## The Gate / Soul Binder divergence (scoped, not built)

The tester found Gate refusing after binding at Maelis. Root cause: **two unconnected bind
systems.** The server bind (`bind_x/y/z`, set by the NPC) drives Respawn; the client bind
(`PlayerStats.bind_zone_path`, set by casting Bind Affinity) drives Gate. The NPC sets the one
Gate doesn't read. And Gate returns you to where you cast it because `set_bind_point` stores a zone
+ entry id, not a position.

Scoped as its own sprint (`e295e93`) — it touches the bind system that caused the first tester's
death loop, so no quick patch. Scoping shrank it: of the "9 PORT spells", only 3 (Gate, Succor,
Evacuate) are blocked on server support; the other 6 point at zone scenes that **have never
existed** (`scenes/zones/` is absent). Content, not engineering.

## The dead-intents audit

Nine wire intents have no client sender. A workflow with an exploit lens sorted them:

- **NPC proximity gate (Medium exploit, OPEN).** Because `Interact` was never built, the server has
  no NPC positions, so **nothing range-checks vendor / bank / quest turn-in**. A modified client
  can bank its whole inventory from a dungeon one second before dying, voiding the gear-loss half
  of the death penalty. Not a mint — but it nullifies a designed consequence. Fix folds in the
  standing "BuyItem ignores vendor_id" gap and the deferred Banker proximity gate.
- **Tradeskills (BUILT, ticked).** See below.
- **Active skills (OPEN, content gap).** Damage multipliers discarded (server rolls a normal
  swing); three effects (Shield Bash, Feign Death, Warder's Fury) throw *silent* runtime errors
  online. No security surface — the swing-rate limiter blocks skill-spam.
- **CancelCast (OPEN, UX).** No player-facing cast abort exists.

Confirmed there is **no item-generation exploit**: all six item-add paths funnel through one server
function, five choose the item server-side, phantom items evaporate on relog.

## Tradeskills: guard shipped (`a065a19`, ticked)

Mining, crafting and skinning created items with a bare local `Inventory.add_item()`, reachable
online. The sharp edge, worse than a ghost: crafting deletes the **real** ingredients from the
client mirror while the server holds them, drifting slot indices so a legitimate Sell/Destroy hit
a *different real item*. All three now refuse honestly online. Real server-authoritative
tradeskills are a later build (new Tradeskill-depth item; pairs with the NPC gate since nodes need
server positions).

## Right-click is the world-interact verb (`fa2ff04`, ticked)

One mouse grammar, requested partly for bot resistance (the old proximity-F path needed no cursor
work — walk near, mash F). Right-click (tap) interacts everywhere; left-click only targets; a
right-drag stays the camera, split by the same 6px threshold. Corpses keep left-click targeting for
res casts. Central router `Targeting.interact_at()`; F chain retired. Playtested all 13 rows, the
camera section clean.
