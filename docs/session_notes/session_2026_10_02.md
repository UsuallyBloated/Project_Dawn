## 1. The range-gate sweep, which became a cast pre-flight

Yesterday's Charm finding (castable on any mob in the world by id) prompted a sweep of the other
target-type arms of the cast resolver. It found:

- **ALLY spells (heals and buffs) had no range check**, on a player target or a pet target. A
  modified client could keep a friend alive in a dungeon from town by naming an id.
- **ENEMY spells against a player had none either.** With both sides flagged for PvP, one could
  nuke the other from across the world.
- AOE is centred on the caster and PET_SUMMON has no target, so both were already bounded.

And one I had introduced on 09-30 with the refund work: refunds ran AFTER the handler had taken
the mana, stamped the cooldown and rolled the casting skill. The refund gave the mana back but
could not un-stamp or un-roll, so a cast the server was always going to refuse was a free
skill-up attempt (mana used to be what rationed those) and still burned its cooldown.

The fix is `cast_target_refusal` (server `fe0e789`, completed in `8e662d6`): one pre-flight,
called before any of those side effects, that decides everything decidable from immutable state.
Every target type is covered: presence, liveness, reach and the PvP gates for ENEMY / ALLY /
PET_CHARM; CORPSE; an AOE with no radius; a summon with no known pet; and any type with no
server arm. A refused cast costs nothing at all.

The review pass mattered again. My first cut returned "fine" for every target type it did not
know, which left the free skill-up open through **Bind Affinity**: no server arm, on ten
classes' bars at level 1, so an honest hotbar got a free Alteration roll every three seconds.
It also found that **one cast bar authorised any number of casts** (every CastSpell in a batch
reads the same CastStart cache), which refusals being free had just made unmetered. One
CastSpell per caster per tick is accepted now.

**Disclosure.** Far, offline and never-existed targets all get one line, and no refusal names
a player. Before, "Unable to attack <name>" answered for any connected char id from anywhere,
the same char_id to name oracle the inspect review caught the day before.

**The honest player's half** (client `228db25`, next export). The client had no spell range
check and starts its own cooldown the moment it sends a cast, so without a client change a
healer would learn the reach only after the cast bar, and a refused Charm would lock itself
for 60 s on the client while the server would have taken it at once. `cast_spell` now checks
the distance first (24 m, one metre inside the server's 25), and the server's refusal is a
private CastFail, which the client uses to drop the cooldown it started.

**A design note for the user, not a hidden decision:** heals now share the nuke's 25 m reach,
because spells have no range field. Say the word if heals should reach further.

## 2. A ban reaches a character that is already in the world

Yesterday's ban closed every way IN (login, session use, world connect) and left one stated
gap: a character already online kept playing until it dropped, and the only lever was a server
restart. The world loop now runs a ban sweep every 10 seconds (server `9b0bf87`, `8e662d6`): it
asks which accounts are banned, sends any matching connection `KickCode::BannedNow`, and drops
the transport a second later so the kick arrives first. From there the character leaves by the
ordinary unclean-exit path: linger, final save, reap. No new teardown code.

From the review: the query runs on its own task and answers over a channel (inline, a read that
waited on a busy database would have frozen every player six times a minute); the grace is
measured from the send; and a kicked connection's messages are ignored, so the kick cannot serve
as a one-second warning to drop valuables for an accomplice.

A password reset still does not kick. Nothing in the database says "end sessions that began
before now", and adding a column for it would make a binary rollback impossible on a migrated
database. `reset_password` names the lever instead: ban, wait for the kick's log line, unban.
