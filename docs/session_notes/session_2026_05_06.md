- Builders return `Dictionary` shaped to `serde(tag = "type")`: `make_register`, `make_login`, `make_char_list`, `make_char_create`, `make_char_delete`, `make_logout`. `email` is omitted from the register dict when empty (Rust side uses `#[serde(default)]` so missing field deserialises to `None`). `class` is reserved in GDScript so the create-character param is `char_class`; the dict key remains `"class"` to match the wire format.
- Wire helpers: `encode_auth(msg) -> String` wraps `JSON.stringify`; `decode_auth(text) -> Variant` returns `null` on parse failure or non-Dictionary payload.
- `CLIENT_VERSION = "0.1.0"` — matches the server's `MIN_CLIENT_VERSION` default. Bump in lockstep.

## Architecture decisions

- **Single-scene UI**: `scenes/main.tscn` is one Control node with `main.gd` attached. The three views (Login / CharSelect / CharCreate) are MarginContainers built programmatically in `_ready()`, all anchored full-rect, toggled via `show()` / `hide()`. No per-view `.tscn` files — keeps everything reviewable in one place and dodges hand-written scene-file parser surprises.
- **Race/class lineup hardcoded** in `scripts/character_lists.gd` (16 races + 18 classes pulled from CLAUDE.md). Pulling `data/character_data.gd` from the client would have dragged in autoload dependencies (PlayerStats etc.) that the launcher does not need. Server validates the chosen race/class on CharCreate, so launcher-side drift surfaces as a server `InvalidInput` error rather than silently breaking.
- **NetProtocol copied** to `scripts/net/protocol.gd`, verbatim from `Project_Dawn/scripts/net/protocol.gd`. Diffed at commit time to confirm zero drift. Both files mirror the Rust protocol crate; keep them in lockstep on every protocol change.
- **Auth host** is editable on the login screen, defaults to `127.0.0.1:8765`, persists to `user://launcher.cfg` along with last-used username. World endpoint is **not** launcher-configured — it comes back in `LoginOk.world_endpoint` and the launcher passes it through to the game.

## `autoloads/auth_client.gd`

- WebSocketPeer wrapper with separate signals: `connected` / `disconnected(was_open)` / `connection_failed(reason)` / `message_received(msg)`.
- Polled every frame in `_process`. Early-returns when never connected, so the autoload sits dormant until the first `connect_to` call.
- State transitions guarded: `connected` only fires on the OPEN edge, `connection_failed` only fires on CLOSED-after-CONNECTING (server unreachable), `disconnected` only fires on CLOSED-after-OPEN (server dropped us mid-session).
- `connect_to(url)` closes any existing peer first so retries don't leak. `send_msg(msg)` no-ops with a `push_warning` if the socket isn't open.

## `scripts/main.gd`

- Login → CharSelect → CharCreate flow:
  - **Login**: validates non-empty fields, queues `make_login` and connects. Server's `LoginOk` stores `session_token` / `account_id` / `is_gm` / `world_endpoint` / `characters`, saves config, switches to char select.
  - **Register**: stashes the password in `_password_pending`, sends `make_register`. On `RegisterOk` auto-sends `make_login` with the held password — user lands on char select in one round trip without re-typing.
  - **CharCreate**: sends the chosen name/race/class. On `CharCreated` re-fetches `CharList` and switches back to the select view (server's `CharCreated` reply is just `{char_id}` so a refresh round-trip is needed to render the new entry).
  - **CharDelete**: same refresh pattern via `CharList`.
  - **Logout**: sends `Logout`, waits for `LogoutOk` to tear down the socket.
  - **Error** reply surfaces as `Error (<code>): <msg>` on the status line; connection stays open so the user can correct credentials and retry.
- `_send_or_queue(msg)`: sends immediately if the socket is open, otherwise queues into `_pending_msg` and triggers `connect_to`. The `connected` signal handler drains the queue. This is what lets the user click Log In once and not worry about whether they're already connected.
- Status line shared across all three views via `_set_status(text)` writing to all three Labels' `.text` (only one view is visible, so the user always sees current status).
- Mid-session disconnect (server kicks us, network blip): `_on_ws_disconnected` clears the token and bounces back to login with "Connection lost. Please log in again."

## Game .exe handoff

`_resolve_game_exe()` looks in three places, first hit wins:

1. `$PROJECTDAWN_EXE` if set and points to an existing file
2. Sibling of the launcher executable: `<launcher_dir>/ProjectDawn.exe` (packaged distribution case)
3. Dev fallback: `F:/Projects/Project_Dawn/builds/ProjectDawn.exe`

If none resolve, the launcher reports the failure on the status line without quitting. On success it spawns `OS.create_process(exe, args)` and the launcher's `get_tree().quit()`s. Args passed:

```
--auth-token=<64-char hex>
--char-id=<i64>
--world-endpoint=<host:port>
--client-version=<semver>
```

The game executable does **not** parse these yet (no world UDP server, no CLI arg handler). They're harmless extras the game ignores; the user lands in the existing client lobby. The handoff *mechanism* is exercised end-to-end though — when the game-side parser ships, the launcher side is already done.
