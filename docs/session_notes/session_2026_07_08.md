# Session 2026-07-07/08 — Quests go online: kill credit, dev world-spawns, group unification, and the quest-XP exploit fix

Both repos, branch `fix/xp-leveling-overflow`, wire **PD_W0022 → PD_W0023** (one bump covers all four
features; `gdext_net.dll` rebuilt). Follows the quest XP tier re-tune (client `315a156`, 2026-07-06).

## What shipped (one changeset, four features)

**1. Quest kill-credit online (`KillCredit`).** The launcher-mode gap where "kill N X" objectives never
advanced (`QuestManager.notify_kill` only fired for local Test-Room enemies) is closed: the server sends a
**private `KillCredit { mob_name }`** to whoever earned a kill, and `net.gd` feeds it to the same
`notify_kill` the local path uses. Deliberately not the `EntityDied` broadcast — witnesses get nothing.

**2. Dev world-spawns (`DevSpawnMob`).** Test Panel spawns were client-local puppets the server couldn't
see. In launcher mode the panel now asks the server (dev-gated like Full Heal, `PD_DEV_CMDS=1`) to spawn a
REAL world mob ~3m ahead: server combat, XP, loot, corpse, quest credit. One-shot (`spawn_point_idx =
usize::MAX`, the pet precedent — no respawn timer). Names hardened (trim, 2-64 bytes, warder-template names
rejected server-side AND the panel mob renamed **"Grey Wolf"** — a charmed bare "Wolf" would have armed the
free warder-respawn loop for any class). NaN payloads rejected (`f32::clamp` propagates NaN — an
hp=NaN mob would be unkillable). Named mobs stay client-local (enrage/loot logic has no server side yet).

**3. Group-split unification (`award_kill`).** The playtest caught that only melee kills split XP/credit
across the group — spell and pet killing blows paid the single top damager. All three kill paths now route
through one `award_kill` helper: liveness-filtered members, 1.2x pool when grouped, per-member floor,
XP + `KillCredit` together. Two deliberate behavior changes: a grouped caster/pet kill now SPLITS (duo =
0.6x each, was killer-takes-1.0x), and **owned victims (player pets, charmed mobs) award NOTHING** — a
warder respawns free every ~15s, so pet kills paying XP was an infinite, group-amplified leveling loop.

**4. Quest-XP exploit fix (server-authoritative rewards).** User-flagged: `GrantQuestXp { amount }` let any
client name its own XP (one forged packet = instant level cap), and the quest-journal wipe on logout made
repeat turn-ins an infinite farm. Now: the client sends only a **quest id** (`CompleteQuest`); the server
looks it up in its own **`data/quests.toml`** (mirror of `quest_definitions.gd`, spells.toml lockstep
discipline), computes the XP itself (tier% x cubic band at `level_req` — `world/quests.rs`), enforces
`level_req`, and records the completion in a new **`completed_quests` table (migration 0009)** — persisted
BEFORE the award, so **a quest pays once per character, ever**, across relogs and server restarts.
`GrantQuestXp` survives dev-gated only (the Test Panel leveling buttons). Quest ids are charset-validated
(snake_case) so attacker strings can't spoof log lines. Quest item rewards gated to Test Room (client-side
grants were ghost items online — server never knew, vanished on relog).

## Review + verification

Three adversarial review workflows across the arc (kill-credit/DevSpawnMob round 1 + 2, quest authority).
Highlights caught + fixed: the warder-"Wolf" quest-farm (owned-victim exclusion), the charm-a-dev-Wolf
permanent-warder loop (rename + server rejection), pet-kill XP as an infinite faucet (owned victims award
nothing), ghost item rewards (gated), `level_req` guard (forged all-ids burst cut from ~55k to ~6.4k XP),
NaN guards, liveness guards + a latent div-by-zero in the group split, and a `continue` that would have
skipped loot spawning. Exploit-surface verified: no non-dev message can mint XP; same-id spam pays once
even within a tick; SQL parameterized; the completed set loads on every login path.

Cautious full-stack verification (user-granted): **155 lib tests** (quest table anchors + completion
round-trip + kill_xp + curve), **full integration suite** — found + fixed a REAL stale assertion (a test
still expected the old flat `mob.xp = 10`; the EQ formula pays `kill_xp(1) = 263`), the other two failures
are the documented pre-existing flakes (pass solo; `flaky_integration_tests.md`), 40/40 individually.
**Boot smoke against the real world.db** (backed up as `world.db.bak-pre0009`): migration 0009 applied,
table confirmed. Clean client boots throughout.
