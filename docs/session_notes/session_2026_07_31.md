### The two bugs this playtest cycle caught (worth remembering)
1. **Loopback exemption** (`6cddff2`) — the original gate skipped 127.0.0.1 "for dev convenience",
   which made it both untestable *and* unprotected in the normal localhost setup. The first re-test
   reported "does not work" purely because of it. Dropped: a login success clears the budget, so the
   dev relog loop never accumulates anyway.
2. **Register never throttled** (`fcfdf9a`) — the launcher auto-logs-in after each Register, and a
   login success cleared the **shared** per-IP counter, so the Register budget reset every account
   (8 accounts in 30 s, no error). Root-caused from `world.db` (each account's `last_login` was ~1 s
   after `created_at`). Fixed by keying the limiter on `(IpAddr, AuthKind)`.

Both were only findable by playtest — neither unit tests nor the 3-lens adversarial review caught
them, because both hinged on real client/launcher behavior.

## Server-authoritative procs — PLAYTESTED + TICKED (PD_W0025)
`server_procs_checklist.md` all `[x]`: proc fires ~1-in-7 with a FIRE flash and the named
"Flaming Strike for 25 damage." line (crit variant seen), damage is real, proc killing blow grants
loot + XP once, non-proc weapons and spells unaffected, dual-wield procs per hand only.

**Two tester questions, both resolved:**
1. *"The weapon might be hitting and proc-ing at the same time"* — **that is the design, not a double
   hit.** The proc rides the swing: the server folds `proc_damage` into that same swing's resolution,
   so the client shows two numbers (swing + proc) and two log lines, but the mob takes **one combined
   HP drop**. Verified in source: `proc_dmg` subtracts from `entity.hp` exactly once (tick.rs:3331,
   the only subtraction), then a single `fan_out_health_update` carries the combined HP. This is
   EQ-authentic (a proc fires on a landed swing).
2. *"Proc killing blow — please confirm"* — **confirmed from the log.** 64 loot bags spawned, every
   `bag_id` unique (no duplicate), and no two bags in the same second — either would be the signature
   of a double death cascade. Clean run: 0 errors, 0 panics.

**Bonus proof the client-side roll is really gone:** this run logged **0 swing-rate rejections**. The
2026-07-29 swing-rate playtest logged exactly 6, all Flamebrand main-hand — the client's old proc
Attack being dropped. Zero now means the client no longer sends it, which is precisely what this
change set out to do. Also visible: `loot bag spawned (spell kill)` lines, confirming the spell path
is untouched.
