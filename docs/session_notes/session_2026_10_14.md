## 4. Seated combat: the classic EQ rule, both halves

The user's call on the corrected research ("Both halves, the P99 rule... sitting near a mob is
now dangerous, as in EQ"). Server `d4f6b47`, client `2495276`, `seated_combat_checklist.md` (16 rows);
the server half works on the client testers hold, the body standing on a hit rides the export.

What exists: `combat::mitigated` is the one home of melee mitigation (`armor / (armor + 100)`
off a standing target, nothing off a seated one), called by the mob swing and the PvP swing
alike; `combat::calc_swing_max` is the top of the attacker's band for a seated PvP target, with
the crit roll untouched (a crit is luck on top of the roll, which is also how EQEmu orders it);
a mob's swing is flat, so for a seated player its max is the amount. The stand is one line in
`PerConnection::note_damage_taken`, which every player-damage site already calls, so the seated
regen rate, `/camp` and the seated rule all end with the first hit. Nothing on the wire carries
the seated flag (Sit and Stand are intents the server never echoes), so the client stands its
own body on the Hit it receives and never on a zero-damage one.

Tests: unit tests for the band max, the offhand multiplier, the mitigation table and the stand;
an integration test where a seated player is hit by bare fists for exactly 4 + STR/5, a `/camp`
straight after is refused (the one intent that needs the server's own seated flag, so it is the
deterministic probe for the stand) and the same `/camp` after sitting again is accepted. It
fails on the previous code at the camp assertion (the camp was accepted). Two harness lessons
from its first drafts, both the harness's own traps: a `send_attack` followed only by the other
client's `wait_for` never services the attacker's socket, so the swing never leaves it; and
`pump_both_for` asserts both clients connected, so it cannot follow a `send_disconnect`. A
headless probe covers the client half. Full suite green (275 unit, 97 integration).

Exploit lens: both rules key on the server's own seated flag, which a client can only set by
sending Sit, so lying about standing forgoes the seated regen and lying about sitting invites
the max roll; there is no way to be seated for the regen and standing for the hit.

## 6. Resurrection sickness, the corpse plan's last piece

The user's "keep going" again. The corpse plan's slice 3 specced a short debuff on res-accept
("reduced stats/regen for a few minutes, via the server buff system") and v1 dropped it; it was
the plan's last open piece. Server `53ad557`, client `fc7688c`, `res_sickness_checklist.md` (12 rows).

Research first: the Project 1999 wiki's Resurrection Effects page (five minutes, "You are
exhausted.", "You feel your strength return.", HP down about three quarters, mana to zero, and
level-scaled cuts to STR, STA, AGI, WIS and INT on EQ's hundred-point stats). The build takes
one point per four levels (floor one) off each of the five primaries and halves natural HP and
mana regen, all as named constants with no user decision behind the numbers, and leaves P99's
one-shot arrival at a quarter HP and no mana as a flagged user call (a bigger change beside the
corpse). **The sizing rested on a wrong claim**, caught by the user the same evening: the note
first said our stats "sit around ten to sixty". The real scale (`char_data.rs`) is base 10, race
plus or minus 20, class up to 18, then a class's main stats gain 1 to 4 a level for life (a
Human Warrior's STR about 22 at 1, 60 at 20, 140 at 60) while every other stat never moves. So
level/4 is a small bite on the main stats and can take a secondary stat negative at high level,
and on the server only STR is read at runtime (melee damage), so the regen halving is the real
sting. Left open for the user with three shapes (the To-Do entry has them).

What exists: `buffs::res_sickness_buff` is a stat buff with negative deltas, so `apply_stat_buff`,
the buff tick's expiry and `undo_stat_deltas` all serve unchanged; the regen tick reads it by
name and multiplies natural HP and mana regen; the accept path applies it, fans the owner's
snapshot and sends the line; the expiry sends the wear-off line. The snapshot carries names
and durations only and the sickness is not a spell the client's additive reconcile can rebuild,
so `BuffManager` recognises it by name and applies the same level-based cut (lockstep by hand),
syncing its remaining on later snapshots and undoing it when the server drops it. Buffs are not
persisted, so a relog clears it, as camping did in classic; flagged as a knob.

Tests: unit (the cut per level, the buff's shape, the regen halving over forty ticks); an
integration test that dies, respawns, has a Cleric 20 cast the six-second Resurrection (Minor)
on the corpse, accepts, and checks the Teleport, the line and the five-minute entry in the
owner's snapshot; a headless probe for the client half. Full suite green (277 unit, 98
integration).
