## The notes held two real bugs, both fixed today

- **Equip-from-hand blanked the held item.** The EquipItem handler's delta fan knew
  base/equip/bag but not "cursor", so an equip-from-hand SWAP fanned an EMPTY cursor delta:
  the client's hand went blank while the server still held the swapped-out piece, and the
  "You're already holding something." refusal the tester saw was the desync's symptom. A sweep
  found five hand-rolled delta readers with the same blind spot — three latent (partial
  drop/destroy from the hand would zero the client's remainder; eat-from-hand was refused at
  the pre-peek). All five now read through `peek_at`. Server-only; 213/213 tests.
- **Drop-confirm clicks passed through to the world.** The confirm dialogs are native popup
  Windows, invisible to the main viewport's hovered-control check, while player.gd deliberately
  polls hardware button state — so the click answering the dialog also registered as a world
  tap and instantly re-opened the prompt. The dialogs now report their closes to Inventory and
  `request_ground_drop` ignores taps inside a 400 ms echo window (which also covers a
  cancelled DELETE echoing into a drop prompt). Client-only.
