# Session 2026-06-19 — Banker NPC slice 2 (item storage)

Built the **Banker NPC slice 2: item storage**, the second slice of the Banker after the
2026-06-17 coin MVP. It adds a per-character item vault and an account-shared vault, plus
one-character-per-account login enforcement, and lands the banking half of the new
**inventory interaction grammar** (right-click quick-transfer). Cross-wire across both repos;
wire bumped **PD_W0015 to PD_W0016**.

Scope was set with the user this session after they authored `docs/design/inventory_interaction_grammar.md`:
**bank-first, minimal grammar** (whole-stack right-click quick-transfer for items and coins,
the full cursor grammar deferred to its own track), and **keep the slice-1 coin buttons**.

## What landed (server `F:\Projects\server`)
- **Storage:** `0006_bank_items.sql` adds a char-keyed `bank_items` table (10 slots) and an
  account-keyed `account_bank_items` table (2 shared slots). One reusable `ItemVault` struct
  (flat fixed-size `Vec<Option<InventoryEntry>>`) backs both: `deposit` (stack-merge then
  first-free, capped at `max_stack`), `capacity_for`, `take_all`, `restore`, `peek`,
  row/snapshot projections. 4 new unit tests.
- **One char per account:** enforced on connect (the design pass found it was NOT enforced
  before, only a token anti-spoof check). A second login for an account already in-world is
  **refused** (`DuplicateLogin`, "You already have a character in this world."); the session
  already playing is never force-disconnected. (Playtest feedback drove this: booting the live session
  on re-login is a known grief / force-off exploit, e.g. Lineage II.) This also keeps the
  account-shared vault trivially single-owner. Tradeoff: after an unclean disconnect the player
  waits out the stale session's timeout before reconnecting; a clean logout frees it at once.
- **Wire (PD_W0016):** `BankStoreItem` / `BankWithdrawItem` client intents (string location +
  `shared` bool, NOT the SlotRef tagged enum the handoff suggested — the design pass caught
  that gdext can't encode tagged enums from GDScript) and a `BankItemSnapshot` server message
  (full vault contents per op, like the coin `BankSnapshot`). Appended at the enum ends.
- **Apply (`tick.rs`):** store sizes the deposit by the vault's room (`capacity_for`), removes
  exactly that from inventory (the removed count drives the deposit, so the inventory side is
  the single source of truth — no dup), rejects bag-typed items; withdraw takes the stack,
  fills inventory, and refunds any overflow straight back into the source vault slot (no loss).
  Both fan `InventoryDelta` (inventory side) + `BankItemSnapshot` (vault side); both vaults are
  seeded on enter-world. Persisted via the checkpoint sweep + disconnect flush (personal by
  `char_id`, shared by `account_id`).
- gdext bridge: `send_bank_store_item` / `send_bank_withdraw_item` + a `bank_item_snapshot`
  signal (parallel arrays) + decode/emit. **DLL rebuilt to PD_W0016** (4.06 MB).

## What landed (client `Project_Dawn`)
- `net.gd`: `broadcast_bank_store_item` / `broadcast_bank_withdraw_item` + the
  `world_bank_item_snapshot` signal/handler. `BankerManager` caches both vaults (resolving
  item paths to `ItemData`), tracks `bank_is_open` + `deposit_to_shared`.
- `BankWindow`: now a TabContainer with a **Coins** tab (unchanged slice-1 controls) and an
  **Items** tab (a 10-slot personal grid, 2 cool-blue account-shared slots, a Personal/Shared
  deposit-target toggle). Right-click a vault slot to withdraw.
- The deposit gesture: `inventory_window.gd` + `bag_window.gd` right-click, **while the bank is
  open**, quick-transfers the whole stack to the selected vault (the section-4 quick-transfer
  from the interaction grammar) instead of use/equip.
- **Coin quick-transfer:** the Coins tab's Carried/Bank balances became per-tier clickable
  chips; right-click a tier to deposit/withdraw that whole tier. The slice-1
  deposit/withdraw buttons and the exchange control stay.

## Adversarial review
4-dimension finder + verify workflow over both repos. **1 confirmed bug fixed + a cluster of
nits resolved/deduped:**
- **BUG (found, then designed out):** the original "kick the older session" enforcement only
  cleared the kicked session's `account_bank_items_dirty` on a *successful* pre-kick flush, so a
  transient DB error there let the kicked session's deferred disconnect flush re-save a stale
  shared vault and **clobber the new session** (item loss). First fixed by clearing the flag
  regardless of flush outcome; then playtest feedback flipped the model to **deny the new login**
  (above), which removes the whole flush-before-kick handoff and the clobber path entirely.
- **STORE (hardened):** was `let _ = destroy_at(...)` then an unconditional deposit (a latent
  dup vector if `destroy_at` ever failed). Now uses the actual removed count and bails on Err.
- **WITHDRAW (hardened):** overflow refund now goes straight back into the source slot via a new
  `ItemVault::restore` (no `max_stack` cap), making the "lands back in the same slot" comment
  true and removing a latent loss path on a corrupt over-cap DB row. Added a partial-fit notice.
- **nits:** BankerManager now `push_warning`s on a vault item that fails to `load()` (was a
  silent display desync); dropped a stale `BankItemDelta` mention from the protocol doc.

## Playtest fixes

- **Refused-login message now displays.** A screenshot showed character B's refused login landing
  on the generic "transport: disconnected: connection terminated by server" instead of the kick
  reason. Two races: server-side, `server.disconnect()` fired right after `send_kick()`, evicting
  the channel buffer before the reliable `Kick` flushed (the same race `leave_session()` avoids);
  and client-side, `_on_kicked`'s own `disconnect_now()` re-entered `_on_transport_disconnected`,
  which clobbered the reason. Fix: the server no longer disconnects the refused connection (it was
  never inserted into `connections`, so the client tears itself down on the kick and the reliable
  reason actually arrives), and `_on_transport_disconnected` now defers to a remembered kick
  reason. The reason is also the user's wording: **"You already have a character in this world."**
- **Note on the "kill A, relog" checklist row:** as run it exercised a *clean* window-close (which
  sends a clean `Disconnect`, freeing the account at once), so the immediate relogin succeeded —
  correct deny-login behavior. A true hard-kill (Task Manager) is the stale-session case the
  camp/linkdead track turns into a deliberate ~30s. See `docs/design/camp_and_linkdead.md`.

## Notes / scope
- **Partial item moves** (grab-half, exact split, drag-and-drop, the server-tracked cursor) are
  the separate cursor-grammar track in `inventory_interaction_grammar.md`, not this slice. This
  slice moves whole stacks via right-click. The bank storage + quick-transfer intent are the
  foundation that grammar builds on.
- One-char-per-account is enforced by refusing the duplicate login (not by booting the live
  session); the account-shared vault is single-owner as a result.
- No proximity gate on bank actions yet (matches the vendor pattern; value-preserving).
