## What it is

Player-to-player trading, escrow by LOCKING (design: `docs/design/trade_window.md`).
An offered item never leaves its owner's inventory — the session stores a
`(location, slot, count)` reference and every other inventory intent that
touches a locked slot is refused. There is no moment where an item lives only
inside a session object, so a crash mid-trade loses the session, never an item.

## Server (both in `F:\Projects\server`)

- **`world/trade.rs`** — the `TradeManager`: one session per player (which
  makes double-session and same-slot-twice free), offers as references,
  `clear_accepts` on every edit (the anti-bait-and-switch law), lock queries
  derived from live sessions. Six unit tests on the state machine.
- **`world/tick.rs`** — the apply block: request (players only, in-world,
  alive, in range, instant open), offer/retrieve/coins (each fans full state
  to both, clears both accepts), and the **commit**. The commit re-validates
  liveness, range, per-tier coin coverage, offered-stack counts (external
  growth would raise what changes hands), and BOTH receivers' capacity via
  cloned placer sims, THEN does the in-memory swap, `db::commit_trade`, and a
  full revert on db failure; deltas defer until the write commits (the
  corpse-loot doctrine). Plus a per-tick range/liveness sweep and escrow
  refusals wired into Move/Split/Drop/Destroy/Equip/Unequip/Sell/BankStore.
- **`db::commit_trade`** — both characters' inventories + wallets in ONE
  transaction (the two-character sibling of `save_stores_atomic`).
- **Protocol** bumped to PD_W0028: six client intents, four server messages.
- **Exploit ledger as integration tests** (`world_two_clients.rs`): atomic
  two-sided commit pays both, an edit clears both accepts and a lone
  re-accept commits nothing, the escrow lock refuses a Move with the line,
  self-trade and coin overdraft refuse. Suites: 235 unit + integration green
  (the charm test's known load-flake isolated, passes alone).

## Client (`F:\Projects\Project_Dawn`)
