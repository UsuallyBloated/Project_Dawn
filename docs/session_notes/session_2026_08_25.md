## 1. The NPC proximity gate (the Medium exploit, closed)

The server gained an NPC position model: `data/npcs.toml` + `world/npcs.rs`, mirroring the four
placements in `world.tscn` (Brom vendor+quests, Aldric quests, Sister Maelis soul binder, Thalia
banker) with the same lockstep discipline as `items.toml`.

Gated: `BuyItem`/`SellItem` (a vendor within range), **all five** bank loops (a banker — this was
the arm that voided the death penalty, banking gear from a dungeon before dying),
`CompleteQuest` (a new optional `turn_in_npc` per quest; Aldric owns wolf_threat/rotfang_hunt,
Brom owns rat_infestation/gnoll_raiders, dev quests stay ungated), and `BindAtCurrentLocation`
(a soul binder — a modified client could otherwise bind at a dungeon floor and respawn there,
self-building the death loop).

**The design decision:** `NPC_SERVICE_RANGE = 15 m`, deliberately looser than the client's 6 m UI
gate. It is a backstop against *remote* abuse (an exploiter is 50 m+ out), and its cardinal rule
is never refusing an honest player over position drift. A unit test pins the constraint that
sized it: the starter spawn must reach every town NPC, because the integration buy/sell tests
transact from spawn. Two new integration tests prove the gate directly — a buy from 200 m out is
refused with no coin change; the same character at spawn buys normally.

Closed two other standing To-Dos in the same pass: "`BuyItem` ignores `vendor_id`" and the Banker
proximity gate deferred from the Banker MVP.

## 2. A flaky-test scare, resolved by A/B

`pet_attacks_owners_target` failed **in isolation** — which my own corrected rule (08-23) calls a
real regression. Stopped and A/B'd: the clean `da36216` tree failed identically in isolation, the
diff adds zero pet/cast code, and the test passed on a re-run. So that test has degraded to
flaky-even-alone, and the rule needs a second clause: **isolation is a heuristic; the A/B against
a clean tree is the arbiter.** Noted for the flaky-tests item.

## 3. Active skills (the audit undersold it)

The audit flagged three skills throwing silent runtime errors online. Tracing the CC surface
found it wider: `spells.gd` calls `root`/`snare`/`apply_attack_slow`/`silence` **directly on the
target**, and `RemoteEnemy` implemented none of them — so every CC spell cast at a server enemy
aborted its own cast function mid-way, invisibly (engine errors never reach debug.log).

- **Honest refusals** for STUN / FEIGN_DEATH / EVADE / ABSORB / STEALTH skills online, *before*
  any stamina or cooldown is paid. The first two crashed; the rest were placebos consumed only by
  `receive_player_damage`, which server damage never calls. The tradeskill rule: refusal beats
  placebo. Damage skills stay usable as normal swings.
- **Warder's Fury actually works now** — one-line redirect to `PetManager.command_attack`, which
  always had a correct wire branch. The old call existed only on the local Pet.
- **CC no-op stubs** on `RemoteEnemy` (six methods) and `RemotePet` (two), the `get_spell_resist`
  precedent: the call lands, nothing visible happens, the caller's remaining work completes. They
  become the application points when server-side enemy CC lands.
- **Corrected a dangerous stale comment** in `tick.rs`: it claimed the client cancels its cast on
  movement (false, then), presenting the server's movement gate as a backstop when it was the
  only defence. Someone would eventually have weakened it on that assumption.

## 4. Cast cancel (the audit's last item)

No player-facing cast abort existed. Now: **movement cancels** (WASD/jump/autorun, the EQ rule),
**ESC cancels before touching windows**, and both **refund the mana instantly** — it was spent
optimistically at bar start, but the server only deducts when the completed cast arrives, so on
every cancel path nothing was ever truly taken. Server interrupts share `cancel_cast` and now
refund too. This also makes the corrected comment's ideal true: the client genuinely cancels on
movement, and the server's 5 m gate is now genuinely the forged-client backstop.

Deliberate call flagged, not decided: classic-EQ interrupts *eat* the mana; wanting that is a
server design change (deduct at CastStart). Accepted cosmetic gap: peers' view of a cancelled
cast bar runs out on its own — fixing it needs the wire intent plus a gdext rebuild.

`CancelCast` the wire intent is now confirmed permanently dead and deletable, alongside
`StackAll` and `TurnInQuest`.
