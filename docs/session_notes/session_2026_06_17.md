# Session 2026-06-17 — Banker NPC slice 1 (coin banking + tier exchange)

Built the **Banker NPC, slice 1 (coins-only MVP)** from `handoff_banker_npc.md` — the
headline feature now that coins drop and have weight. The Banker is a town NPC offering
**zero-weight coin storage** (deposit/withdraw) and **tier exchange** (convert coin between
tiers). It's the relief valve for the four-tier coin-weight system: bank your heavy copper
and carry nothing. Cross-wire across both repos; wire bumped **PD_W0014 → PD_W0015**.

Scope was locked with the user this session (4 decisions + 3 defaults; see the handoff's
"Decisions (LOCKED)"): **coins only** (item storage incl. the 2 account-shared slots is
slice 2), **0% fee** exchange + **free** banking for the MVP, exchange on the **carried
wallet**, a **new `BankWindow`**, `bank_*` columns on `characters`, `BankRejected` for
failures. Design contract: `docs/concepts/world/currency.md` → "Banking & Currency Exchange".

## What landed (server `F:\Projects\server`)
- **Persistence:** migration `0005_bank.sql` (four `bank_*` columns); `bank_coins` +
  `bank_dirty` on `PerConnection`; `db::save_bank` + `load_character` mapping + `SpawnRow`;
  gated saves in the checkpoint sweep (`persistence.rs`), the disconnect flush (`tick.rs`),
  and an enter-world `BankSnapshot` seed so the client caches the balance on login.
- **Coin math (`protocol`):** new `Coins` helpers — `exchange` (value-preserving tier
  convert; up-conversions must be whole multiples; Err leaves the wallet untouched),
  `has_at_least` / `add_each` / `sub_each` (per-tier, saturating), `has_negative` (rejects
  mint-via-negative). 6 new unit tests.
- **Wire (PD_W0015):** `ClientWorldMsg::{BankDepositCoins, BankWithdrawCoins, BankExchange}`
  + `ServerWorldMsg::{BankSnapshot, BankRejected}`, **appended at the enum ends** (bincode
  discriminant stability); `WORLD_PROTOCOL_ID` bumped.
- **Handlers + apply:** `Outcome::Bank*Intent` + dispatch; tick apply loops that validate
  (non-negative, affordable, whole-multiple) then fan `CoinsUpdate` (wallet) + `BankSnapshot`
  (bank), or `BankRejected`. `handlers::send_bank_snapshot` / `send_bank_rejected`.
- **gdext bridge:** `send_bank_deposit/withdraw/exchange` + `bank_snapshot` / `bank_rejected`
  signals + `Incoming` + decode/emit. **DLL rebuilt to PD_W0015** (4.04 MB).

## What landed (client `Project_Dawn`)
- `net.gd`: `broadcast_bank_deposit/withdraw/exchange`, `world_bank_snapshot` /
  `world_bank_rejected` signals + handlers + the gdext signal connects.
- `BankerManager` autoload — proximity + open (mirrors `VendorManager`), caches the
  server's bank balance for display. `BankerNPC` + `scenes/banker_npc.tscn`; **Thalia
  Mourne** placed in the town hub (`world.tscn`). `targeting.gd` + `hud.gd` route the
  `banker_npcs` group to `BankerManager`.
- `BankWindow` (`scripts/bank_window.gd`, mirrors `vendor_window`): wallet + bank rows,
  per-tier deposit/withdraw, tier-exchange controls. Server-authoritative — sends intents,
  refreshes off the `CoinsUpdate` / `BankSnapshot` fans (no optimistic mutation).

## Adversarial review (`/code-review`-style workflow)
4 finder dimensions (server-economy / wire / client / integration) → adversarial verify.
**1 confirmed bug + 4 minor, all fixed bar one documented nit:**
- **BUG (fixed):** `targeting.gd` click-to-target only set `vendor_npcs` / `dialogue_npcs`
  as the current target, so a `banker_npcs` NPC could never be targeted → the BankWindow was
  **unreachable in-game** (the hud interact path reads `Combat.current_target`). Added
  `banker_npcs` to the friendly branch.
- **cleanup (fixed):** `Coins::{add_each, sub_each, adjust_tier}` used unchecked `i64`
  arithmetic vs the type's saturating discipline → made saturating.
- **nit (fixed):** `bank_window` cleared the entry spinboxes optimistically on send, so a
  rejected deposit wiped the typed amounts (contradicting its own "wait for the fans"
  header) → now clears only on the confirming `BankSnapshot`; a reject keeps the amounts.
- **nit (fixed):** stale `net.gd` comment naming GroupManager as the reject logger.
- **nit (documented, no change):** bank actions gate only on `in_world`, no Banker-NPC
  proximity check. Value-preserving (the math is server-validated) and matches the existing
  vendor Buy/Sell pattern, so not a regression — noted for a future proximity-gate pass.

## Method note
Built bottom-up with a compile gate at each layer (foundation → wire → handlers → DLL →
client), per the loot-track method note. The PD_W0015 wire change followed the append-only
enum rule from the start (a mid-enum insert was the exact bug that bit the last session's
review). The adversarial-review workflow earned its keep again: the targeting gap would have
shipped a feature you literally couldn't open.
