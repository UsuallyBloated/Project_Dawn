# Session — 2026-05-13

**Track 5 — Server-authoritative enemies.** Four sub-tasks landed
across two repos. After this track, two `.exe` instances on one
server see the same enemies in the same positions, watch each other
fight them, kill them in sync (server owns enemy HP), and pick up
loot from server-broadcast bags with FFA arbitration. The Track 4
trust model (own HP / own MP / own inventory) carries forward; only
enemy state is fully server-authoritative.

`WORLD_PROTOCOL_ID` bumped once for the whole batch:
`PD_W0003 → PD_W0004`. Five new variants under that id:
`ServerWorldMsg::EnemySpawn`, `::EntityTarget`, `::LootBagSpawn`,
`::LootGranted`; and one ClientWorldMsg shape change:
`Attack { target_id, amount, crit, dmg_type }` (was a no-payload
stub).

## Sub-task 1 — Enemy state on the server (3 commits)

Foundation. Per-mob templates ported from `Project_Dawn/data/zone_data.gd`'s
`STARTER_ZONE_CAMPS` into `crates/projectdawn-server/data/zone_camps.toml`
(9 camps, 27 spawn points, 9 archetypes). `crates/projectdawn-server/src/world/`
gains three new modules: `zones.rs` (TOML loader + camp/mob types),
`entity.rs` (`Entity` struct + `EnemyState` enum + AI tick method
driving Idle/Chase/Attack/Leash transitions against a snapshot of
in-world player positions), and `spawn_points.rs` (`Spawner` with
respawn timers — backdates first spawn so it fires on tick 1, then
arms a per-camp respawn cadence on death).

Enemy id partition starts at `ENEMY_ID_BASE = 1_000_000_000` so the
client routes shared signals (Position / HealthUpdate / EntityDespawn)
by id alone. Server tick gained step 4g (spawner) and step 4h (AI
tick) before the existing move-integration step; step 6b fans out
enemy positions alongside player positions every tick. New constant
`ATTACK_RANGE_TOLERANCE = 1.5` gives the client room to be slightly
behind the server's position view without rejecting legitimate melee
swings.

Integration tests: `enemies_visible_after_enter_world` (sub-task 1B)
asserts ≥1 EnemySpawn arrives after EnterWorld; `enemy_aggros_chases_and_attacks_player`
(sub-task 1C) walks the player into camp 0 and asserts an EntityTarget
+ Hit broadcast targeting the player.

## Track 4 fix — Step 4a seed is symmetric

User-reported regression while verifying sub-task 2: client A targets
client B, B's HP/MP/Stamina render as 0/0/0 until B triggers a state
change. Root cause: step 4a seeded the new joiner with each existing
peer's cached resource / cast / buff state, but only sent identity
(EntitySpawn) in the other direction. If A entered the world first
and B's lobby `apply_character` broadcast B's initial resources
before B clicked Enter World, A received the HealthUpdate but
dropped it via RemotePlayerManager's `if not _spawn_data.has(id)`
guard (no EntitySpawn for B yet). When B finally EnterWorld'd, A got
the EntitySpawn but no resource seed — record sat empty until B's
next ResourceUpdate (which only fires on state change).

Fix: step 4a's "New client → existing peers" loop now also sends
B's cached resources / cast / buffs to each existing peer.

## Sub-task 3 — Player attack intent + death lifecycle (3 commits)

`ClientWorldMsg::Attack` repurposed from no-payload stub to
`Attack { target_id, amount, crit, dmg_type }`. Per the handoff Q4
option (a), the client embeds the damage amount; server trusts and
applies. Track 6 lifts to fully server-authoritative combat math.

New tick step 4h (apply attack intents): validates target alive,
attacker in range (`melee_range × ATTACK_RANGE_TOLERANCE`), applies
damage, fans Hit + HealthUpdate to in-world peers, transitions to
Dead on HP=0 and fans EntityDied. Range / liveness failures produce
a Miss broadcast so the attacker still gets visible feedback.

New tick step 4j (corpse cleanup): scans dead enemies, after
`CORPSE_LINGER_SECS = 5.0` fans EntityDespawn and arms the spawn
point's respawn timer via `spawner.on_enemy_died(spawn_point_idx)`.

Client side: `combat.gd` gains `_apply_damage_to_node` chokepoint
that picks the right authority — RemotePlayer → broadcast_hit
(visual only), RemoteEnemy → broadcast_attack (server resolves),
local Enemy → local take_damage (Test Room). All three damage call
sites (melee, single-target spell, AoE spell, weapon proc) converge
on it. `_spell_to_net_damage_type` maps SpellData's authoring enum
(FIRE/ICE/.../HEALING/NONE) onto NetProtocol.DamageType.

Integration test: `player_attack_kills_enemy_and_corpse_despawns`
walks player into camp 0, waits for an enemy Hit (proves in melee),
one-shots the Decrepit Skeleton with `Attack(amount=999)`, asserts
HealthUpdate(hp=0) + EntityDied + EntityDespawn arrive in order.

## Sub-task 4 — Server-authoritative loot bags (4 commits)

Per handoff Q3 option (b): server owns loot tables and bag lifecycle;
clients render and submit pickup intents. FFA arbitration (first
arrival wins).

New `crates/projectdawn-server/src/world/loot.rs`: 11 mob loot tables
ported from `Project_Dawn/data/loot_tables.gd` (`MobLootTables.TABLES`)
with the same partial-match resolution semantics ("Decrepit Skeleton"
→ Skeleton table). `roll_for_mob` returns `Option<Vec<LootItemStack>>`
where None means no bag at all (empty roll or unknown mob).

`LootBagSpawn { bag_id, pos, items: Vec<(String, u32)> }` snapshot
wire shape — server re-broadcasts the whole bag on every state
change rather than diff-applying. `LootGranted { item_path, count }`
is a private confirmation to the looter that the stack landed.
Bag id partition: `LOOT_BAG_ID_BASE = 2_000_000_000`, above enemies.

New tick step 4ka (apply loot intents): validates bag, range, slot
bounds; removes the requested stack(s); sends LootGranted privately;
re-broadcasts LootBagSpawn (if items remain) or EntityDespawn (empty).
Step 4k bag-expiry timer (`LOOT_BAG_LINGER_SECS = 120.0` mirrors
the GDScript local timer) catches unlooted bags.

`autoloads/remote_loot_bag_manager.gd` mirrors RemoteEnemyManager;
on `LootBagSpawn` for an existing id, reassigns `bag.items` and
emits `items_changed` so the open LootWindow refreshes without the
manager coupling to it.

`scripts/loot_bag.gd` and `scripts/loot_window.gd` adapt without
forking. `LootBag.bag_id: int = -1` is the discriminator: `< 0` is
a local single-player bag (legacy path, 120s timer, direct
Inventory.add_item); `>= 0` is server-owned (timer skipped,
LootWindow.Take routes through `Net.broadcast_loot_item`,
server's LootGranted handler does the Inventory.add_item).

## Tests

`cargo test --release`: 27/27 stable across multiple back-to-back
runs (8 lib unit + 3 auth + 1 world_smoke + 9 world_two_clients + 2
protocol + 4 spawn_points/zones/loot unit tests). cargo clippy clean.

Late timeout bump on the two AI-driven tests (`enemy_aggros_chases_
and_attacks_player`, `player_attack_kills_enemy_and_corpse_despawns`)
from 10s → 20s. With 9 parallel tests in the file each spinning up
its own server task, CPU contention pushed the AI tick + position
fan-out behind by a few seconds under `cargo test --release` —
isolated runs complete in 5-6s, parallel was hitting 12-15s. Bumped
timeouts eliminate the flakiness without slowing the happy path.
