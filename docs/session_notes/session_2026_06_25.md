# Session 2026-06-25

## Corpse epic Slice 3 — Cleric / Paladin Resurrection — BUILT, awaiting playtest (NOT committed)

Cross-wire, both repos, **PD_W0021 -> PD_W0022**. The capstone of the corpse epic: a Cleric (or Paladin)
resurrects a dead player's corpse, summoning them back to it and refunding a percentage of the XP that
death cost. Built here from the build-ready plan (`docs/design/corpse_slice3_resurrection_plan.md`) after
the user locked all 8 forks this morning.

**Locked decisions (2026-06-25):** summon-back model (you respawn naked at bind on death as before; a res
teleports you back to your corpse + refunds XP — it doesn't revive you, you're already alive); **no
res-sickness in v1**; **Cleric + Paladin** (3 Cleric tiers + 1 Paladin tier); reject an offline owner;
allow a zero-loss (sub-lvl-5) corpse res (summons, refunds 0); store the **nominal** lost xp; **double-res
guard** (persisted); same-zone only.

**A verification catch:** the plan said move the res spells to a "Restoration" casting skill — but there
is **no `restoration` discipline** in the code (the disciplines are evocation/alteration/abjuration/
conjuration/divination, and every Cleric heal is `alteration`). So the res tiers stay on **alteration**,
not a nonexistent skill. (Caught by reading the real `DISCIPLINE` map.)

### Phase A — lost-XP capture + persist
`apply_death_penalty` discarded the death's xp loss; now it stamps the nominal loss on
`PerConnection.death_lost_xp` (0 for grace), which the corpse-creation pass threads onto the new
`Corpse.lost_xp` + a new `corpses.lost_xp` column (migration `0008`, which also adds `resurrected`).
`save_corpse` / `load_corpses` / `CorpseRow` carry both; boot-load restores them. db round-trip test added.

### Phase B — the spells
Replaced the single inert `Resurrection` (target NONE, alteration) with **3 Cleric tiers**
(`Resurrection (Minor)` 25% / `Resurrection` 50% / `Resurrection II` 75% instant) **+ 1 Paladin tier**
(`Reclaim Soul` 20%), all `target_type "CORPSE"`, in BOTH `data/spell_definitions.gd` and server
`spells.toml`; new `res_xp_percent` field on the server `Spell` struct (server-authoritative refund).
Added `CORPSE` to the client `TargetType` enum + `_parse_target_type` + a `_cast_target_id` corpse branch.

### Phase C — server cast / offer / accept + wire
New `"CORPSE"` arm in the spell target dispatch (`tick.rs`): validates (res tier, caster Cleric/Paladin
at level, corpse exists + in range + not already rezzed, owner in-world), records the offered % on the
owner's `PerConnection.pending_res_offer` (so the accept can't forge the %), and sends a private
`ResurrectOffer`. New `ResurrectAccept` -> `Outcome::ResurrectAcceptIntent` -> a tick loop that
re-validates against the recorded offer, marks the corpse `resurrected` (in-memory + `db::set_corpse_
resurrected`, persisted), **teleports** the player to the corpse (`conn.pos` + a new `Teleport` message),
and **refunds** via `progression::award_xp` (re-levels + fans XpGained/LevelUp for free). Wire: appended
`ClientWorldMsg::ResurrectAccept` + `ServerWorldMsg::{ResurrectOffer, Teleport}` (PD_W0022), gdext signal
+ Incoming + decode + emit + `send_resurrect_accept`; DLL rebuilt.

### Phase D — client
`corpse.gd` left-click now also `Combat.set_target(self)` (so a Cleric can target a corpse); `hud.gd`
`_on_target_changed` got a `Corpse` branch (shows "<owner>'s corpse", no HP bar — without it the
friendly-NPC branch would throw on the missing `npc_name`). A HUD **Accept/Decline res prompt** driven by
`Net.world_resurrect_offer` -> `Net.send_resurrect_accept`. `net.gd` relays `resurrect_offer` + `teleport`
(snaps the local player to pos on summon).

**Verified:** server build + **148 lib tests** (incl. the lost_xp round-trip + a res-tiers assertion);
clean editor boot.

**Pre-playtest adversarial review (4 dimensions: XP-dupe/exploit, server flow/borrow, wire/privacy,
client) — 5 confirmed (all minor/nit), all fixed:**
1. **Level-5-floor over-refund (the important one).** Storing the NOMINAL death loss let a res at the
   level-5 floor (where the de-level is clamped) refund MORE than the death actually cost — net-positive
   xp from dying, a small grind exploit. Fixed by storing the **ACTUAL** xp removed
   (`progression.rs`: capture pre/post, `death_lost_xp = pre_xp` when the floor clamped us, else `loss`).
   This intentionally adjusts the locked "store nominal" fork (#6) — the exploit framing contradicts the
   honest-refund intent; flag to the user.
2. **Re-res on a persist failure.** `set_corpse_resurrected` failure was only logged, so a restart could
   reload the corpse un-rezzed and allow a second refund. Fixed to **persist the flag FIRST**, granting
   the res only once durable (`continue` on failure; a fresh cast retries).
3. **Stale res prompt** could be Accept-clicked into a server no-op after the corpse despawned. Fixed
   client-side: the HUD hides the prompt on the corpse's `EntityDespawn`.
4. **No client CORPSE pre-cast gate** — a mis-cast burned a long res cast + mana before the server
   rejected. Added a CORPSE gate in `spells.gd` mirroring the ENEMY gate. (All re-verified: 148 tests +
   clean boot.)

**PLAYTESTED + COMMITTED 2026-06-26.** Two-client run confirmed the full machinery: all FOUR tiers (the
3 Cleric + Paladin `Reclaim Soul`) fire end-to-end (cast → offer → Accept prompt → teleport-to-corpse →
XP refund at the right 25/50/75/20% proportions), plus every guard (decline, double-res, offline-owner,
out-of-range, class gate) and persistence across a server restart. Test aids added: a Test Panel
**"Level Up"** button (one click = one server-authoritative level — the Cleric tiers were blocked only by
the test Cleric being too low-level to afford the 100-300 mana, not by any bug); res spell mana/cooldown/
level were briefly lowered to test values then **restored before commit**.

**Surfaced a separate, pre-existing bug (NOT Slice 3):** at very high levels the geometric ×1.5 XP curve
(`char_data::xp_to_next_for`) overruns `i32` and **saturates at `i32::MAX` (~2.1B)**, so a high-level
death "loses" 5% of a 2.1B band (~107M) and the res honestly refunds a % of that (the giant refund
numbers in the log). This likely also explains the tester's earlier **"de-level to level 1"** report (the
floor-at-5 de-level math fed garbage at the integer ceiling). Queued as a follow-up: flatten the
high-level XP curve or move XP to `i64`, AND root-cause the de-level-to-1.

This completes the corpse epic's core. Deferred follow-ups: **XP-curve / i64 (+ root-cause de-level-to-1)**,
