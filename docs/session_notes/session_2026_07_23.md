## Bug the playtest surfaced: skills show `1 / x` after relog — FIXED + PLAYTESTED (client `0f0489b`)
> Playtested clean 2026-07-29 (`skill_display_relog_checklist.md`, all `[x]`): trained skills show
> correct values immediately on relog (both fresh-open and window-open-across-relog), no bogus
> CombatLog "skill increased" spam on login, live advance still ticks, and all three skill kinds
> (weapon / armor / casting) restore correctly. server.log clean (0 errors, normal relog session).

Tester's note: "combat skills reset to 1/x when I re-login; when they increase the correct numbers
appear and replace the 1/x ... appears persistent on server side but skills don't load on login."
**Diagnosed as a stale DISPLAY, not lost data.** Verified the whole chain against source:
- Server LOADS persisted skills correctly (`seed_starting_scores` then overlay `character_skills`
  rows, tick.rs) and SENDS the loaded values on EnterWorld (`send_skill_progress_snapshot`, line
  2199, self-directed). So the scores are right server-side.
- Client applies them: `apply_remote_snapshot` overwrites the (already-initialized) key set. Order
  is correct on relog — `apply_character`/`initialize()` runs on ConnectOk in the lobby, before
  Enter World is even sent, so the keys exist when the snapshot lands. Data ends up correct.
- The gap: the character window paints skills in its `_ready` `_refresh()` at **world load**, which
  runs BEFORE the snapshot arrives (a network round-trip later), and `apply_remote_snapshot`
  updates the cache **silently** — it deliberately doesn't emit `skill_advanced`, because CombatLog
  subscribes to that and would log a bogus "Your <skill> increased to N" three times on every world
  entry. So the labels never repainted; they sat at the seeded `1 / x` until the next real advance
  (which does emit) snapped them to the correct value. That exactly matches the report.
- Fix (client `0f0489b`): a dedicated `snapshot_applied` signal on `PassiveSkillTracker`, emitted
  once at the end of `apply_remote_snapshot`; the character window connects its three refreshers to
  it. CombatLog does NOT subscribe, so no bogus advance lines. Headless project import is clean.
  Re-test: `skill_display_relog_checklist.md` (needs a re-export).
