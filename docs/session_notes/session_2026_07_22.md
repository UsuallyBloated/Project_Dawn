## Bug the cast-gate playtest surfaced: client/server spell drift (FIXED for the 2 reported)
The tester's notes flagged Blood Mage **Life Drain** and Shadow Knight **Dark Shroud** doing nothing
(mana spent, "You cast X", no effect). **Root cause (confirmed in `server.log`: 5 "unknown spell"
drops, casters 126/128): both existed only in the client `spell_definitions.gd`, missing from the
server `spells.toml`.** `spells::lookup` returns `None` and drops the cast **before** the class/level
gate runs — so this is unrelated to the gate (and confirms the gate only ever sees real spells).
Ported both as base-class `ENEMY` spells (server `e6a3542`); Life Drain is a lifetap — the
`apply_spell_damage_to_enemy` caster-heal path already handles `heal_amount` on ENEMY. Their
`DISCIPLINE_MAP` entries were already present, so casting-skill credit was already in lockstep; only
the stat blocks were missing. New test locks both against re-drift (172 lib tests). Re-test:
`spell_drift_life_drain_dark_shroud_checklist.md` (server restart only, no re-export).

## Phase 1 gate: Attack weapon_path trust (finding 5) — BUILT (pending playtest)
The `Attack` message's `weapon_path` is now ignored server-side; the resolver derives the swung
weapon from the SERVER's equipment map (slot 0 main / slot 1 off, protocol `EquipSlot` order) via a
new `PerConnection::equipped_weapon_path`. Server `9089b4b`. Closes the audit's "Attack trusts the
client's weapon_path": a modified client could name a heavier weapon (more damage), a ranged one
(more reach), or one that trains a skill it hasn't equipped. All five consumers (the `calc_swing`
damage roll, the PvP + enemy range checks, the out-of-range log, the weapon-skill advance) now read
the derived path. An empty slot is an unarmed 1-4 fist / `hand_to_hand` swing (bare-handed combat
unchanged); `is_offhand` now only selects the slot, so a client can't fabricate an off-hand swing it
isn't geared for. **Verified safe before shipping:** equipping only ever routes through the
server-side `EquipItem` intent (client `equipment.gd` → `broadcast_equip_item`), and `from_rows`
restores the equipment map from DB on connect, so the map is authoritative + in sync for anything
worn; `create_character` seeds no gear, so fresh characters start bare (correctly unarmed until they
equip). `weapon_path` dropped from the `Outcome` + local intent (received-but-ignored, like
`EquipUpdate` armor); wire unchanged, **no client re-export**. +1 unit test
(`equipped_weapon_path_reads_the_server_slot`), 173 lib. Playtest: `attack_weapon_path_checklist.md`
(regression sweep — a stock client always sends its real weapon, so the exploit path is unit-test +
log covered). Dev-tool note in the checklist: a Test-Panel ghost weapon now swings as fists (server
never saw it — correct); use `/give` + paperdoll equip to test a real weapon.
